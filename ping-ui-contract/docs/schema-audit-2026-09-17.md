## Cross-cutting findings

1. **Envelope placement divergence (envelope schema).** The JSON contract requires maturity/source at top level; index.mjs writes and validates them under `_envelope`. Fix direction: pick one canonical placement, document it in the ADR, add a contract test that loads each JSON schema and asserts the chosen placement, and align `withEnvelope`/`validate` with it. Until then the JSON schemas and the runtime helpers enforce two different contracts.

2. **MUTABLE? is no for all 17.** Every schema in this package represents an as-of state snapshot or value, not an intent. Mutation/intent typing (e.g. OperatorPingClient gap-labeled intents) lives in packages/api-client, outside this package. If intent schemas are added later, they must carry an explicit intent marker so no consumer mistakes state for a mutation grant.

3. **Trust-surface columns are unclassified for almost every schema.** Per ADR section 0 resolution 3 and open question 2, route-by-route data classification (esp. SENSITIVE_PUBLIC fields) is still OPEN. No schema in this package may be treated as proven-safe for the public surface on schema evidence alone, except where a schema is a pure wrapper (envelope, pagination). The capability schema's trust_surface enum is PROPOSED vocabulary, not enforcement.

4. **Namespace is correctly silent everywhere else.** No schema other than namespace.json makes namespace claims, and none implies per-tenant scoping. This is the right default under ADR boundary A; keep it that way if a namespace field is ever proposed for the envelope.

5. **Weakest authority grounding (ranked):** run (explicitly none), capability (PROPOSED names only), identity (tenant kind references a nonexistent file), authority (names with no read path), artifact (model cited, no read path), worker (no fleet read path), projection (meta-type, no registry). Strongest: automation-health (RUNTIME_VERIFIED against real captures), event, mission, envelope, error, pagination (IMPLEMENTED with tests).

## Resolution record (2026-09-17, same day)

Cross-cutting finding 1 (envelope placement divergence) was resolved: all 16
non-envelope schemas now compose the envelope under `_envelope` via `$ref`
to envelope.json, matching what `withEnvelope` writes and `validate()`
checks. Enforcement establishes sovereignty, so the JSON contract was
aligned to the runtime enforcement rather than the reverse. No v2 was
required because no surface is WIRED or DEPLOYED. A contract test asserts
the canonical placement for every schema. Optional `generated_at` was added
to envelope.json as the only approved additive field (projection build
time, distinct from `verified_at`).
