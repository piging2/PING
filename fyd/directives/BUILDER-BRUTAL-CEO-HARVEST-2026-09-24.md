Nolan's ecosystem notes accompanying this order (2026-09-24): Sanity's current Content Source Maps map individual returned values back to their source document and field; its visual editing layer uses that metadata for overlays, direct editing, drag/reorder. FYD takes that idea one level deeper: a rendered sentence traces to the PING object, evidence, and original external source that justified it — answering "who owns no invented claims?" without inventing another giant authority; factual rendering is valid only when the projection binding traces it backward. Payload reinforces the other half: typed block structures plus live preview are enough for a capable editing experience; no arbitrary page code as persistence model. Sanity's latest drag-and-drop relies on structured arrays for reorderable sections — evidence that keeping FYD's SiteSpec declarative is the right seam. Caution: current Next.js is 16.3 (materially different caching/build behavior, active security servicing); the older FYD surface is associated with 14.1. Do NOT upgrade during the product proof; log it as a compatibility/security backlog item. Four builder decisions set: media = ingest authorized public demo media into FYD derivatives with source/digest/provenance, not permanent hotlinks; owner gate = real owner authentication/authorization before consequential edits, narrowly labeled demo mode only if auth blocks today's preview; Ask FYD = full evidence-backed Q&A that explicitly says when evidence is insufficient; must-wins = mobile usability, service/action discoverability, trust/provenance, conversational customization, performance.
