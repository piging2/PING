# FYD Performance Baseline (2026-09-24)

Measured read-only against :3100 on the Pig (http://127.0.0.1:3100, localhost).
Wire sizes measured with curl --compressed (gzip), i.e. what a browser receives.
Localhost: network latency NOT representative. Server rebuilt once mid-measurement
(chunk hashes shifted); final numbers from the post-rebuild run.

## What could not be measured and why

LCP, CLS, INP on a mobile viewport: no usable Chromium on the Pig. Both
playwright-bundled binaries (chromium_headless_shell-1243 and full
chromium-1243) fail to launch: missing system library libnspr4.so.
Installing system libraries would be a system change outside this read-only
lane, so it was not attempted. The engagement stack's headed Chrome
(CDP :9223) is owned by the Facebook worker and was not touched.

## Biggest cost drivers (measured)

1. /images/ping-social-logo.png: 1.6 MB for a 120x80 logo on happy-place.
   ~5.6x the entire JS+CSS+HTML combined. Single biggest item by far.
2. Framework JS: ~465 KB raw across framework chunks + 112 KB raw polyfills.
   Top 5 chunks = 77% of all JS.
3. happy-place hero hotlink is a 404: fragile AND broken, confirming the
   directive's ingest-into-FYD-media requirement.
4. Coppersmith is the healthy reference: FYD-served webp derivatives,
   ~390 KB total page, no hotlinks.

## Builder-constraint recommendations

1. Image budget: 300 KB total image weight per page, 150 KB max per image.
   The media pipeline must auto-downscale or reject oversize assets at
   ingest; resizing the logo to display size removes ~85% of happy-place's
   real-world weight.
2. No render-critical hotlinks: above-the-fold media must be FYD-served
   derivatives only. The happy-place hero 404 is the live proof.
3. JS budget: 300 KB gzip total JS per site, 60 KB gzip per chunk; audit the
   112 KB raw polyfills chunk (legacy-browser cost) and keep non-interactive
   content server-rendered (hydrate only islands).
4. Enforce in the builder: SiteSpec build fails or warns loudly when budgets
   are exceeded, so performance stays a constraint, not a post-hoc audit.
