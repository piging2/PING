## What survived

- Idempotency is real, not claimed: event_id = sha256({event_type, source, namespace, payload}), timestamp stripped from identity. Re-emitting the identical observation returned the same event_id (8ad47542...) and the DB holds exactly one row. The runtime counts it as `deduplicated`.
- Restart durability is real: after `docker restart ping-gateway`, both the original observation and the controlled contradiction were readable from ping_runtime.ping_events with source `api:muse` intact. No duplicate rows, no lost provenance.
- Contradictions are preserved, not collapsed: the two Faith Roofing observations (no-website vs website-found, different brief_ids) coexist as separate events. The observation layer does not merge disagreement into one fact. (Whether the downstream claim layer would collapse them is untested; worker cognition is template-level.)
- Provenance stamping works: every event carries source `api:muse` from the auth middleware, plus brief_id in payload.

## What broke (during this red-team, by my own hand, now being repaired)

1. v2 meta-pass.sh shipped with a stream-buffering bug: `PACKINFO=$(builder 2>&1)` merges stderr (unbuffered) ahead of stdout (block-buffered when piped), so PACKFILE received the `PACK_VERSION=` line. Every run with v2 built a prompt without the pack.
2. I rewrote meta-pass.sh while the catch-up chain's bash was executing it. Bash parses scripts incrementally, so the running copy was corrupted mid-flight (`-o: command not found`, slug b marked INFRA worker_failed after its answer was actually saved).
3. Slug c consequently ran degraded: brief-only prompt, while its sidecar recorded a pack version the prompt never contained. A provenance lie, caught before ingestion.
- Repair: chain killed, script fixed (stdout/stderr captured separately, never merged), syntax + pack-step dry-run verified, clean re-run of b/c/d launched. Operational lesson: never rewrite a script while a bash process is executing it; never merge streams you parse separately.

## What silently degraded

- Slug c's degraded run would have looked normal in every log except the stderr nobody watches. The sidecar would have asserted pack provenance the run didn't have. Detection required reading the script, not the outputs.
- The gateway currently reports `/health` = unhealthy (qdrant "fetch failed", embedding "not_initialized") while `/events` serves 200 and agents POST blindly. Partial degradation of the semantic/projection layer is invisible to every consumer.

## What the architecture still lacks (ranked by leverage)

1. **Gateway startup/readiness contract.** The DB startup race is a real defect: DB unavailable -> gateway boots degraded/in-memory -> agents treat it as durable. Smallest fix: block listen (or fail fast) until PG is connected; if degraded mode is intentional, disable mutations while degraded and make the state externally visible. The /health authority already exists; nothing gates on it. REQUIRES AUTHORIZATION (gateway code change).
2. **Evidence lineage conformance.** The worker contract now demands: raw artifact -> extracted observations (statement + source span + confidence) -> source evidence -> per-observation verification results -> preserved contradictions/uncertainty -> PING events linked to raw artifact -> PING-derived claims. Current: one line per business, no raw_artifact link, no per-observation records. Achievable with existing primitives (event_data is freeform; sidecar schema extension). REQUIRES DECISION on where per-observation records live.
3. **Explicit research result states.** success / malformed / incomplete / failed-capture / quarantined / retry-pending / unrecoverable, recorded per brief in the intel dir, so the scheduler knows what needs replay without relying on chain epilogue. Small; no new infrastructure. REQUIRES AUTHORIZATION (new state file convention).
4. **Pack source references.** Stamp source artifact paths + content hashes + generation timestamp into each pack. A few lines in the builder. REQUIRES AUTHORIZATION (trivial, but a change).
5. **Agent-side readiness check.** emit-observation.py should consult /health (or a PG-backed probe) before POSTing. Tiny. REQUIRES AUTHORIZATION.

## Post-report finding: the encoding defect (root-caused 2026-09-13 ~09:45)

The clean re-run's slug C answer came back as CJK mojibake. Root cause, proven against the byte-exact Pig original (pulled via scp):

- The Pig's meta-ask.js writes clean UTF-8, no BOM.
- The v2 pull path used PowerShell `Get-Content -Raw` (re-encodes unpredictably) plus a "try utf-16 first" heuristic.
- `bytes.decode('utf-16')` on even-length UTF-8 ASCII never throws; it pairs bytes into CJK. Slugs B and D survived only because their byte counts were odd (decode threw, fallback hit UTF-8). Slug A (original) and slug C were even-length and silently corrupted.
- This is exactly the failure mode the pre-red-team notes warned about ("arbitrary even-length UTF-8 may decode without throwing and still become gibberish"). The warning existed; the code did it anyway.

Repair: slug C recovered byte-exact from the Pig original (5728 clean UTF-8 chars); corrupted pull quarantined; sidecar regenerated with a recovery note. Slugs B and D verified byte-identical to remote (modulo one leading newline). Step 4 of meta-pass.sh replaced: scp pull (byte-preserving) + BOM-aware decode, strict UTF-8 otherwise, fails loudly instead of guessing. Slug A still needs a clean re-run; rotation.txt already points at A so the next scheduled pass handles it.
