# FYD Public Read-Path Map (read-only audit, 2026-09-25)

Mission: trace every PUBLIC read path from canonical object/evidence state to the serialized browser response in the FYD codebase at `/home/nolan/projects/ping` (Pig). No code changed.

## Architectural fact that frames everything

`getPingObjectGraph` / `getPingObjectGraphSync` (`src/fyd/data/ping-object-source.ts`) return the **full graph including `visibility: "private"` objects** to every caller. The word `visibility` appears exactly once in that file, and only to *validate* that the field exists, never to filter. All privacy is applied per call-site via one of four gate idioms: `publicGraph` (spec-pipeline.ts:59), `applyPublicVisibilityGate` (edge/resolve.ts:62), `publicGraphOf` (ask/visitor-answer.ts:211), and inline `visibility === "public"` checks. **Any surface that forgets to apply the gate leaks.**

## Routes that serve owner history or raw evidence to anonymous viewers

1. **`GET /api/fyd/projection?siteId=`** — serves the RAW graph (private objects, full provenance, dump meta) to anyone. Deliberate "SOURCE SAYS X" design, but it is the single biggest raw-evidence exposure: private objects included.
2. **`GET /api/fyd/objects/[objectId]`** — serves `history`: the owner's human-language action log (`{at, text}` from `reduceOwnerEvents`, owner-events.ts:147-157) to anonymous viewers. Labeled "for the Manage surface" in the route doc, but unauthenticated.
3. **`GET /api/fyd/customize?siteId=&view=inspect`** — serves owner presentation-intent state (directives, approver identity + timestamps, hidden-section decisions) with no gate.
4. **`/dev/objects` lab** — serves private objects' fields (including phone/email via `genericObjectView`) over plain HTTP, gated only by obscurity.

## Bypass class (one paragraph)

The codebase has exactly one privacy mechanism, `visibility === "public"` filtering, but it lives at the **consumer edge, not the data layer**: the canonical read seam `getPingObjectGraph[_Sync]` hands every caller the full graph including private objects, and each surface must remember to apply one of the four gate idioms (`publicGraph`, `applyPublicVisibilityGate`, `publicGraphOf`, inline checks). The failure mode is therefore **omission at each new surface, never a single choke-point failure**: the projection endpoint deliberately skips the gate, the dev lab never got one, the customize inspect GET was written without the demo/private-host check its sibling POST actions carry, and the objects endpoint gates the object but serves the owner's action history alongside it. Owner-side state (correction history, presentation-intent directives, hidden-section decisions) is a second, unmodeled confidentiality class: the gates only understand object visibility, so owner state leaks through routes that are "public" by the object-visibility definition. Any new read surface added without copying a gate idiom will leak by default, and the SiteBundle (full graph, projection left to consumers) is the standing loaded gun for the next one.
