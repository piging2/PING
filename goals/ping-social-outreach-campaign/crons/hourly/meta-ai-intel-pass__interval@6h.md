PHASE B - DISTILL SWEEP (bounded dead-letter recovery):
3. Run `python3 ~/workspace/tandem/distill-sweep.py --select --cap 5`. The discovery job's ingest rounds are the primary path for new answers; this sweep is the dead-letter safety net for captured answer files that were never processed (extracted/verified/distilled). It selects by staleness (see phase C) and excludes out-of-scope briefs (j/k clowning) and quarantined briefs (fail-closed: their answers are evidence only). Process AT MOST 5 selected files per cycle: for each, run the standard verification (independent web search per named business, evidence-graded CONFIRMED/STRONG INDICATION/WEAK INDICATION/UNKNOWN), extract qualified prospects per the standing pipeline rules, then record the outcome with `python3 ~/workspace/tandem/distill-sweep.py --mark <file> distilled|distill_failed "<note>"`. A file that fails verification fails closed: mark distill_failed with the reason, never promote unverified claims.
   CAP RATIONALE: a cycle runs at most 2 fresh prompts and each fresh answer itself needs full verification, which is the costliest work in the pass (~10-15 independent searches per answer). 5 bounds the sweep to a single turn's work envelope so recovery can never starve fresh research; the current queue drains in ~3 cycles (~18h) at this rate. The cap is a ceiling, not a target: process fewer when the queue is short or a primary run needs the time.
