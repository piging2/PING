## 1. PRODUCT ARROW

RESULT -> JUDGMENT -> AUTHORIZED EFFECT. The domain question: HOW DOES PING JUDGE WHETHER A RESULT IS GOOD ENOUGH TO BECOME ACTION? JEV becomes the typed shadow judge of real FYD and ORCA outputs, measured against a deterministic baseline and a defined gold set, and earns influence only with evidence. It never seizes the wheel: production routing and effects stay with the baseline and CG-001 until a convergence decision says otherwise. Downstream product motion served: ASK FYD answers get judged for support quality (unsupported claims caught, correct refusals recognized) and failure triage gets routed faster, both in shadow, both measurable, neither promoted until the ledger says the evidence is there.

## 4. SEMANTIC OWNER

JEV is the JUDGMENT PLANE, one vertical over the PING semantic/control plane. Semantic owner of: the question "is this result good enough to become action," the typed judgment shape, the judgment dimensions (FACTUALITY, RELEVANCE, COMPLETENESS, POLICY, SAFETY, EVIDENCE QUALITY, CONTRADICTION, UNCERTAINTY, ACTIONABILITY), the verdict vocabulary (once archaeologized, never before), the per-tier budget semantics for judgment calls, and the evaluation-metadata schema for shadow comparisons. It does not own: the result/finding content being judged (ORCA/FYD own their findings), the mission, the route, the effect authorization, or the verdict's consumption (consumers own their tiers, gates, and answer paths).

## 6. INPUT CONTRACT

Typed inputs JEV judges in shadow. Two primary input families, each frozen by its owning sprint:

A. ASK FYD GOLD SET (owned by sprint 04, consumed by JEV). Per-question record: question id, question text, source website identity, expected supported facts, required evidence refs, allowed evidence refs, forbidden claims (unsupported-claim traps), expected epistemic status (including expected refusal where appropriate), coverage class (directly supported / multi-object / relationship-dependent / unsupported / contradicted / ambiguous / privacy-hidden / owner-corrected). JEV's job: judge whether the produced answer is supported by the cited evidence, catching unsupported claims in shadow while the deterministic baseline remains production authority.

B. ORCA FINDING SETS (owned by sprint 03, handed through the MC seam from sprint 02). Per-set record: finding-set digest/reference, source digests, observations, claims with evidence refs, contradictions, uncertainty marks, executor/version, correlation/run identity, next-action proposal. JEV's job: judge claim support (SUPPORTED / PARTIALLY_SUPPORTED / CONTRADICTED / INSUFFICIENT_EVIDENCE / POLICY_BLOCKED / UNCLEAR are CANDIDATE labels pending archaeology), route failures for investigation, never mark fixed.

Input integrity requirements: every input carries a digest; JEV judges digested inputs, never raw private context; tenant identity excluded at the boundary.

## 13. ACCEPTANCE TESTS (integration-truth terms)

AC1. Shadow evaluation complete and honest. The gold set runs through CURRENT baseline and CURRENT+JEV shadow; every metric (unsupported claims, correct refusals, evidence correctness, useful-answer rate, false blocks, latency, cost) is computed and recorded; the result is stated as measured lift or honest no-lift. Falsifiability: re-run with shuffled JEV scores; if "lift" persists, the metric is broken, not the reranker. Replay: candidate-set digest + question-definition version + pinned model version reproduce the comparison.

AC2. Shadow classification routes without ever fixing. 100% of JEV-classified failures in nightly/weekly tiers carry a typed route observation; zero records show JEV marking a failure FIXED/RESOLVED/CLOSED; MayExecutePolicy holds (allowed=false in every consumed decision). Falsifiability: inject a fabricated route observation claiming FIXED; the consumer must reject it or the invariant check fires.

AC3. Quarantine cannot recur by construction. Every new JEV call carries owner authority from creation; a probe attempting a call with --owner-id stripped at every layer (CLI, direct run(), courier) fails closed with zero provider calls. The 29 quarantined missions are untouched. Falsifiability: run the stripped-owner probe; any provider call means FAIL.

AC4. Attestation integrity holds under drift. Any provider response not matching the pinned build (jev-1.13.0, attested per jev_contract.py) is rejected and never consumed; a model-version change invalidates shadow baselines via the drift detector. Falsifiability: replay the 2026-09-26 router incident shape (requested pinned build, got router/luna echo); expect ATTESTATION_REJECTED with a ledger record and no consumption.

AC5. Safe metadata only. Every jev-evaluations.jsonl record passes the validator: no raw state, no private context, no secret-shaped values, no tenant identity, hashes only. Falsifiability: submit a record containing a raw prompt with a tenant identifier and a secret-shaped string; the validator must refuse the write.

AC6. Budget discipline. Per-tier budgets enforced before dispatch; an exhausted tier refuses new calls with zero provider spend; total lane spend stays under the $5/day ceiling; per-call cost recorded. Falsifiability: exhaust a tier budget in a probe; the next call must refuse before any provider traffic.

## 14. HOSTILE TESTS

- Fabricated FIXED observation: submit a route observation claiming a failure is fixed; verify the tests-ladder consumer rejects it (supports AC2).

- Scope bleed: verify no JEV output path can reach a gate configuration, a mission creator, or a retrieval mutator (static check over the call graph plus the AC2 probe).

## 15. REPLAY/RECOVERY TEST

Replay: given a jev-evaluations.jsonl record, the triple (question-definition version, candidate-set/finding-set digest, pinned model version) must reproduce the typed judgment comparison deterministically enough to audit (verdict-stability threshold from P1 applies; below-threshold taxonomies are excluded from replay claims).

Recovery: (a) model version deprecation mid-sprint: the contract fails closed, shadow baselines are explicitly invalidated, and a re-pinning follows the same evidence bar as the original pin (direct-call verification, attestation rule update, tests re-run); (b) attestation failure storm: every dependent shadow comparison is marked INVALID, not silently degraded; (c) budget exhaustion mid-tier: outputs are marked PARTIAL_COVERAGE, and clustering outputs carry the coverage flag rather than pretending at completeness.

## 16. OBSERVABILITY
