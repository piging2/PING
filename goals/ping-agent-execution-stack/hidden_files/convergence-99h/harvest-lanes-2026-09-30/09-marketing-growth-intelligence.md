### Candidate A: Always-valid sequential inference (confidence sequences / mSPRT)

PRODUCT NEED -> A mathematical license for the 30-post discovery protocol: a way to look at interim experiment data without inflating the false-positive rate, and a principled rule for when a hypothesis is established, inconclusive, or refuted. CRX HARVESTABLE IMPLEMENTATION -> None.

EXTERNAL IMPLEMENTATION -> VERIFIED against primary sources, read 2026-09-30. (1) Johari, Pekelis, Walsh, "Always Valid Inference: Bringing Sequential Analysis to A/B Testing" (arXiv 1512.04922): proves a one-to-one correspondence between monotone always-valid p-value processes and sequential tests; the mixture Sequential Probability Ratio Test (mSPRT) is a test of power one, meaning the user can wait essentially indefinitely to detect small effects or concede inconclusiveness. This is the exact mathematical shape of "prefer INCONCLUSIVE over fake learning." (2) Howard, Ramdas, McAuliffe, Sekhon (2021), "Time-uniform, nonparametric, nonasymptotic confidence sequences," Annals of Statistics 49(2): the general uniform-boundary framework. (3) Waudby-Smith and Ramdas (2021, arXiv:2010.09686; journal version 2024): the closed-form variance-adaptive empirical-Bernstein confidence sequence, Theorem 2. (4) gostevehoward/confseq on GitHub (verified live): C++/Python implementation of uniform boundaries, confidence sequences, and always-valid p-values, citing exactly these papers. (5) Industry convergence confirmed: Optimizely's stats engine is built on mSPRT (developed with Stanford researchers); Eppo and GrowthBook both ship sequential testing; multiple independent practitioner writeups confirm the discipline "fixed-horizon or sequential declared up front; never stop a fixed-horizon test early because it hit significance."

REACHED/UNREACHED -> REACHED. Papers verified (arXiv IDs confirmed in search output), confseq repo verified live (early-stage, README itself says "should not be considered stable", last meaningful activity ~266 days ago, C++14 + Boost build requirement).

DUPLICATION RISK -> If we hand-roll peeking rules: HIGH. Every team that invents its own "look when it feels significant" rule rediscovers p-hacking. If we port the published method: ZERO, nothing competing exists locally.

SECURITY/TRUST BOUNDARY -> The math is a theorem, not a service. The confseq package is third-party code with a C++ build chain; do not take it as a dependency. The boundary is zero if we port the closed-form construction ourselves: it is ~100 lines of pure Python (running sums, a boundary function from the published paper), with no network, no state, no authority.

SMALLEST DELTA -> One deterministic, pure-function module in the PING-side Python tooling (NOT a new authority, NOT a store): given the observation stream for one experiment (per-post metric deltas tagged with the experiment's hypothesis record), it computes the always-valid confidence sequence and reports one of three terminal states: CROSSED (established), EXCLUDED (refuted), OPEN (keep observing). Wire it as the scoring behavior behind the EXPERIMENT_RUN result JSONB, so the projection contract's `outcome` field and the weekly Sunday review read from a machine, not from prose judgment. The pre-registration (hypothesis, primary metric, MDE, alpha) stays in the mission payload where the compounding directive already puts it; the sequence enforces it. Start with the empirical-Bernstein construction (bounded metrics like engagement rates fit it naturally); the craftbot/gallop discipline adds the honesty rule: if anyone peeked before the sequential design existed, recompute against the always-valid bound and label the result salvaged, not designed.
