What we did not verify. Whether our gateway code ever issues SET or START TRANSACTION. Whether the append-only triggers actually block writes. They were inspected read-only, never tested. Our trials ran on Postgres 16. The journal runs 17. The docs indicate parity. We did not trial it. We did not inspect any pooler or proxy between the gateway and the database. We did not map the full extent of what can be written to disk under read-only, beyond the operations we tested. The next mission is already queued: test the triggers on a disposable database. No writes against the journal. That stays out of scope. We thought we had sealed our journal with a setting. The evidence said we had a default, an unverified assumption, and untested triggers.
