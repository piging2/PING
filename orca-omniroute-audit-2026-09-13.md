## 4. TRANSPORT ABSTRACTION

- **Live workers**: in-process. `WorkerRuntime.dispatch()` calls `await entry.worker.handle(event)` directly in the gateway Node process — no serialization, no subprocess, no HTTP (`worker_runtime.js:84-91`). Transport = function call.
- **ORCA worker ports**: the abstraction is `WorkerPort.execute(mission, context)` → `await this._executor(mission, context)` (`worker_port.js:115-144`). **But the only registered port, `OpenCodeWorkerPort`, is constructed with `executor: null`** (`engine.js:~100`), so `execute()` returns `{ error: 'no_executor', confidence: 0, findings: [] }`. No CLI spawn, no HTTP call exists in the port. The engine never calls `execute()` anyway (§2); the actual "transport" is HTTP round-trip by an *external* agent: GET prompt via `/orchestration/missions/:id/dispatch`, POST results to `/orchestration/missions/:id/output`.
- **Ollama**: HTTP to `OLLAMA_BASE_URL` (default `http://localhost:11434`) for model listing (`ollama_provider.js:3`), but discovery is off and no port is ever constructed from discovered models in production.

## Verdict

1. **Can the fabric route a capability request from an exterior agent (e.g. Muse over SSH) to a worker today? PARTIALLY.**
2. The HTTP surface is live: `POST /orchestration/missions` (with `requiredCapabilities`) → `POST /orchestration/missions/:id/dispatch` assigns `opencode:local` via real deterministic capability selection — but assignment only *builds a prompt artifact and waits*; the sole worker port has `executor: null`, so nothing executes.
3. The only path that actually executes work end-to-end today is the **live PING spine** (`EventToMissionBridge` → `MissionRuntime` → `MissionScheduler` → `WorkerRuntime.dispatch` → canonical workers, in-process), and it routes on **event types, not capabilities**.
4. OmniRoute (capability → provider → connector routing) exists only as a TypeScript spec (`constitutional-compiler/runtime/OMNIROUTER.md`); there is no implementation to reuse.
5. **Single smallest missing piece:** give the ORCA engine a real executor — a ~30-line function passed as `executor` to `OpenCodeWorkerPort` in `engine.js:initialize()` (e.g. spawn the `opencode` CLI with the built prompt, or POST it to the local Ollama HTTP endpoint) — or, honoring the no-new-infrastructure constraint, route exterior requests through the existing live spine instead, which already executes in-process.
