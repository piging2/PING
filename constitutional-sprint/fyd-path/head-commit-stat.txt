    Gate owner mutation behind demo-owner-mode
    
    Product/security blocker: POST /api/fyd/objects/[objectId]/overrides
    evaluated the seeded demo owner chain with no env/host gate (its own
    docstring admitted no production authentication). Both stages (propose
    and approve) now require DEV/DEMO OWNER MODE: the same demoDenied
    contract as the customize approval API (NEXT_PUBLIC_FYD_DEMO_OWNER_MODE=1
    AND a localhost/private-network host via isPrivateHost). Anything else
    fails closed with a typed 403 { ok:false, code:"demo_owner_mode_required" }
    before any object I/O; nothing is written. Visitors may still read via the
    GET object routes and Ask FYD.

      PINGs canonical signed-envelope path to the repo-booted gateway
