## One-paragraph verdict

Tenant isolation exists in exactly one place — the adapter's FYD site layer (`siteId` as tenant id, the `TenantContext` contract in `src/fyd/tenant/`, `requireTenantContext` on the ask/overrides routes, `meta.siteId` + `graphDigest` verification on dump reads) — and even there it is **partially adopted** (routes still call the unscoped stores directly; `scoped-*` wrappers are used only by the builder lane and tests). Below that layer the substrate has **no tenant concept at all**: the core gateway's `ping_events` journal accepts **unsigned canonical-shape event appends** (`POST /events` raw branch), the social ingest adapter **never binds envelope subject/author to the signer**, identity minting is **open**, and the adapter's FYD social BFF takes `actorId` from an **unauthenticated request body** and signs with escrowed keys. Net: tenant A *can* touch tenant B — at the journal level (forge overlays/relationships/posts for any site/identity), at the BFF level (act as any dev identity; demo-owner mode is controller-of-every-site), and at the read level (ungated `customize?view=inspect` and object-history GETs). The client-side visibility filter (`visibleTo`) holds but trusts gateway-supplied `visibility`/`controllerId`, which the forged journal can falsify.

## Per-row WHY → EVIDENCE → MINIMUM CHANGE → TEST → RESULT

### SEC1-01 — unsigned canonical journal append
- **WHY:** `ping_events` is the only replayable store; attestation gates, Ask FYD overlays, and projections all treat "in the journal" as "happened". An unauthenticated append path makes every downstream consumer forgeable.
- **EVIDENCE:** `gateway/routes/events.js`, `router.post('/')`: the `if (req.body && req.body.type && req.body.payload && !req.body.event_type)` branch normalizes+verifies; the `else` branch (raw `{event_type, aggregate_id, aggregate_type, event_data}`) calls `eventRuntime.emit(...)` directly. `gateway/route_middleware.js` has no auth. (Also note the adapter's own `emitOverlayEvent` in `src/fyd/customize/server.ts:78-` uses exactly this shape, so the unsigned format is exercised in-repo.)
- **MINIMUM CHANGE:** require a verified BFF envelope for ALL `POST /events` shapes: route the canonical branch through `verifyBffProof` (or a gateway-held allowlist of trusted emitters, e.g. mTLS/service token for server-side emitters like `emitOverlayEvent`), or delete the raw branch and make every emitter sign. Do not just add a shared secret in the body (it would be logged by `route_middleware`'s body logging).
- **TEST:** `POST /events` raw shape without proof → expect 400/401; with valid proof → 200; existing `gateway/test_events_routes.js` extended with an auth-negative case.
- **RESULT:** PROPOSED ONLY (read-only scope). Not applied.

### SEC1-02 — signer-subject disconnect in social ingest
- **WHY:** signature verification proves "a known identity signed", but the journal records `subject`/`authorId` from free payload fields; attribution is the security property and it is unchecked.
- **EVIDENCE:** `gateway/social_ingest_adapter.js`: `normalizeBffEnvelope` computes `spkiDerHex` and passes it ONLY to `normalizeObjectUpdated`; `normalizeRelationshipCreated(payload, baseMetadata, createdAt)` (lines ~225-256) and `normalizeObjectCreated` (`authorId = payload.authorId || payload.identityId || payload.controller`, lines ~202-204) never see the signer. `normalizeObjectUpdated` resolves `signerId` (lines ~258-275) but never compares to the object's `controller`.
- **MINIMUM CHANGE:** in `normalizeBffEnvelope`, resolve `signerId` once and enforce: `RELATIONSHIP_CREATED.subject === signerId`; post/profile `OBJECT_CREATED.authorId|identityId|controller === signerId`; `OBJECT_UPDATED`: load the target object's current `controller` from the journal and require `signerId === controller` (allow a bootstrap exception for genesis objects with an explicit, logged policy).
- **TEST:** unit tests on `normalizeBffEnvelope` with (a) subject≠signer → `SUBJECT_SIGNER_MISMATCH` 400; (b) authorId≠signer → 400; (c) OBJECT_UPDATED by non-controller → 400; (d) all self-consistent → ok. Extend `gateway/test_social_ingest_adapter.js`.
- **RESULT:** PROPOSED ONLY. Not applied.

### SEC1-03 — unsigned FYD_SITE_OVERLAY
- **WHY:** overlays compose directly into Ask FYD answers per site; unsigned overlays = cross-tenant answer injection.
- **EVIDENCE:** `src/fyd/customize/server.ts:78-` `emitOverlayEvent` POSTs `{event_type:'FYD_SITE_OVERLAY', aggregate_id:'fyd-site:'+siteId, ...}` with no proof to `FYD_CUSTOMIZE_GATEWAY_URL`; `src/lib/ping/ping-object-reader.ts:277-` accepts any event whose `p.siteId` matches.
- **MINIMUM CHANGE:** sign overlay envelopes (reuse `buildSignedEnvelope`/`signAsFydIdentity` with a per-site owner key, or the demo actor key in demo mode) and verify in the reader path or at the gateway; record `approvedBy` actor in the overlay event so `queryFydSiteOverlays` can attribute. Pair with SEC1-01's fix (the unsigned branch is the transport).
- **TEST:** forged overlay for site B (wrong/no signature) → rejected before journal append or filtered at read; legit demo approval → still flows.
- **RESULT:** PROPOSED ONLY. Not applied.

### SEC1-04 — open identity minting
- **WHY:** enables SEC1-02 (attacker needs only a key bound to SOME identity).
- **EVIDENCE:** `gateway/routes/identities.js:97-` `router.post('/')` — field validation only, no auth; minted identity's `controller` = itself.
- **MINIMUM CHANGE:** gate `POST /identities` behind the same emitter-auth as SEC1-01 (gateway operator allowlist), or require an invite/operator-signed mint request. At minimum, rate-limit and audit-log mints with source IP.
- **TEST:** unauthenticated `POST /identities` → 401; operator-signed → 201.
- **RESULT:** PROPOSED ONLY. Not applied.

### SEC1-05 — unauthenticated actorId in social BFF routes
- **WHY:** the BFF holds the private keys; the route lets any caller choose whose key signs. This collapses the social identity boundary at the adapter's front door.
- **EVIDENCE:** `src/app/api/fyd/social/follow/route.ts:21-33` (`body.actorId` → `followIdentity(actorId, targetId)`), `post/route.ts:18-35` (`body.identityId` → `createFydPost(identityId, ...)`); `src/fyd/social/actions.ts:124-` `relate()` signs as `actorId`; `src/fyd/social/key-custody.ts:67` `signAsFydIdentity` loads the escrowed key for whatever id it is given.
- **MINIMUM CHANGE:** bind actor to a session: use the FYD session cookie (`src/fyd/identity/session.ts`, HMAC-signed) or require the caller to prove key possession (challenge-response) instead of handing the BFF an arbitrary `actorId`. Minimum honest step: derive `actorId` from the authenticated session and reject body-supplied `actorId` (mirror the `TENANT_CLAIM_KEYS` pattern in the overrides route).
- **TEST:** `POST /api/fyd/social/follow` with `actorId` ≠ session identity → 403; matching → 201.
- **RESULT:** PROPOSED ONLY. Not applied.

### SEC1-06 — demo-owner-mode total tenant collapse (extends known F3)
- **WHY:** tenant isolation in the owner lane is one env flag + a spoofable Host check away from "anyone is every site's controller".
- **EVIDENCE:** `src/fyd/owner-mode/capability.ts:59-91`; `demoDenied` in `overrides/route.ts:117-` and `customize/route.ts:52-` reads `req.headers.get('host')`.
- **MINIMUM CHANGE:** derive the private-host check from the server's actual bind/listener info or validated `x-forwarded-host` allowlist rather than the raw `Host` header; add a build-time assertion that `NEXT_PUBLIC_FYD_DEMO_OWNER_MODE` is unset in production builds (per SECURITY-SWEEP follow-ups).
- **TEST:** request with spoofed `Host: evil.com` while bound to a public interface → 403 even with the flag on.
- **RESULT:** PROPOSED ONLY. Not applied.

### SEC1-07 — partial tenant-contract adoption + ungated reads
- **WHY:** the `TenantContext` contract is CANONICAL_LAW but routes bypass it; two GETs expose other tenants' owner-state.
- **EVIDENCE:** `grep` for `scoped*` callers (non-test): only `src/fyd/builder/object-builder.ts`, `planner.ts`; `customize/route.ts:109-` GET has no `demoDenied`; `objects/[objectId]/route.ts:25-44` serves `readOverrides(objectId).history`.
- **MINIMUM CHANGE:** route all store access through the `scoped-*` wrappers (authority-map #28's "only sanctioned consumption path"); gate `customize?view=inspect` behind `demoDenied` (or the future owner session); strip owner `history` from the public object GET or gate it.
- **TEST:** `GET /api/fyd/customize?siteId=<other>&view=inspect` without demo gate → 403; with gate → 200; object GET no longer includes `history` for non-owners.
- **RESULT:** PROPOSED ONLY. Not applied.

**Chain B — cross-identity social forgery (rows 04+02):** Attacker `POST /identities` `{displayName:'x', handle:'x1', publicKey:<own ed25519>}` → gets `identity_<hex>`. Then `POST /events` BFF-envelope shape `{type:'RELATIONSHIP_CREATED', payload:{subject:'<victim-identity>', predicate:'follows', object:'<attacker-identity>', status:'active'}, proof:{signature:<valid sig with own key>}}`. `verifyBffProof` passes (own key is bound); `normalizeRelationshipCreated` never checks `subject === signer` → journal records victim follows attacker. `GET /api/fyd/social/state?identityId=<victim>` then shows the forged follow. **Chain C — BFF-level impersonation (row 05):** Attacker `POST /api/fyd/social/follow` `{actorId:'<victim>', targetId:'<attacker>'}` — no auth on the route. BFF `relate()` → `buildSignedEnvelope(victim, ...)` → `signAsFydIdentity(victim)` loads victim's escrowed private key from `FYD_DEV_KEY_DIR` → valid signature → gateway accepts (row 02's missing check doesn't even matter here — the signer IS the victim). **Chain D — demo-mode any-tenant owner mutation (row 06, extends F3):** With `NEXT_PUBLIC_FYD_DEMO_OWNER_MODE=1` and a private-host `Host` header, `POST /api/fyd/objects/<tenant-B-object>/overrides` `{stage:'approve', command:{...}, baseStateDigest:..., baseViewDigest:..., patchDigest:...}` → `createOwnerContext(objectId)` → `DEMO_OWNER_ACTOR` resolves controller-of-every-site → `applyOwnerCommand` writes tenant B's `data/fyd-owner/<B>.json`. **Disproved:** filesystem path traversal for tenant escape (row 09: all store paths validated before `join`); Ask FYD owner-mode leaking private facts (explicitly visitor-safe); claim-machine demo-context guard (happy-place/coppersmith-plumbing unclaimable); overlay siteId confusion at the reader (strict equality filter).

## Summary for the coordinator

- **Tenant identity sources:** request route path (ask/overrides `[siteId]`/`[objectId]`, slug-validated), request body (legacy flat ask route, slug-validated + mismatch-refused; social routes, **unvalidated**), unsigned practice cookie (viewer only, no capability), demo-owner-mode (Host header + env flag — known F3), gateway envelopes (Ed25519 signature → known identity, but **subject/author not bound to signer**).

- **Blast radius note:** the social/journal forgeries (A, B) also defeat the C4 attestation gate by construction (it attests re-reads of a forgeable journal) and the BFF `visibleTo` filter (it trusts gateway-supplied `visibility`/`controllerId`).

## Fail-closed requirements (stated once, referenced by the matrix)

- **F-C1 (mutation/auth):** Owner mutations must be bound to a verified per-tenant identity, not a global demo flag. Routes must consume the `scoped-*` wrappers (or equivalent) so a caller cannot self-declare another tenant; overlay events must carry a signer proof bound to the siteId claim and the gateway must authorize signer→siteId (controller relationship) at emit; the read path must verify the proof, not just the siteId string. Until then, the demo flag must never be enabled on a network-reachable build.
- **F-C2 (reads):** The raw-projection endpoint must project to the viewer's visibility (or require a controller identity) — a digest-verified dump is not a visibility decision.
- **F-C3 (memory):** Every vector search must carry a mandatory tenant/namespace payload filter (fail closed when the filter is absent); memory records need a tenant field; gateway event reads must scope by namespace or require it. Tenant isolation must not live only as client-side filtering in the adapter.
- **F-C4 (projection transport):** Projections must be visibility-projected BEFORE serving or before passing to client components; never ship raw graphs to the browser. A private object must be unrepresentable in any unauthenticated response body, not merely unrendered.

## Next adjacent gap

**The identity-namespace split blocks every tenant-isolation fix.** All four attacks' fail-closed requirements assume a verifiable caller→tenant binding, but none exists: OIDC sign-in mints uuidv5 identities (`src/fyd/identity/principal.ts:57`), the gateway mints `identity_<16hex>` (`src/fyd/social/actions.ts:62`), and owner mutations run as the demo-owner actor (`src/fyd/claim/identity.ts:16` deliberately unbridged).
