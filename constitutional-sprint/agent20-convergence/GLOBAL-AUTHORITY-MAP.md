### CP-1 — HTTP ingest boundary authority: who decides event construction on `POST /events`?

**Claim A — CanonicalizationService is the boundary.** `gateway/bootstrap/gateway_runtime.js` constructs one `CanonicalizationService` wrapping `UnifiedEventRuntime`; `POST /ingest` routes through `authorizeNamespace` + `canonicalizeAndEmit` (canonicalization_service.js:109-176). The 2026-09-16/17 live capture shows `POST /events` patched to route through the same pair (malformed namespace → 403, unauthenticated → 401; event `5e24e593f6a9f7b762ecedfed45a447faba57b6d1d9dded1dacd28feab3fe443` persisted). Evidence: EVENT-FORENSICS.md §2D write path 1; identity/id-prefixes.txt (truth-matrix row 1).

**Claim B — `POST /events` emits through the spine directly with per-copy normalization.** Worktree copy (`/home/nolan/ping`, branch `refactor/runtime-authority-convergence`): BFF `social_ingest_adapter`/`knowledge_ingest_adapter` normalization branch, no tenant check. Src/build copies (identical sha256 `ad9b9c92…`): tenant-registry validation + `namespace = tenant::<id>`, then `eventRuntime.emit` — no `authorizeNamespace`/`canonicalizeAndEmit`. Evidence: EVENT-FORENSICS.md §2D "Copy divergence".

**Conflict:** Claims A and B are both live-sourced but match NEITHER Pig-side copy exactly, and the two Pig-side copies disagree with each other. The same route makes different authorization decisions depending on which copy is deployed.

**Recommendation:** Name `CanonicalizationService` the single ingest authority (it already owns namespace auth + canonical envelope construction); route `POST /events` through `canonicalizeAndEmit`; fold the tenant-registry validation and the BFF normalization branches into its namespace resolution as configuration, not as divergent route code. **Do not converge the route copies before B1 is closed** — a live read-only probe (malformed-namespace POST → 403 vs 400 vs 200) or a container source export is required first (needs parent approval — touches the live container). Agent 01 owns this case (patches/agent01-event-authority/ created 2026-09-24 02:00 UTC; proposal not yet landed).
