## Provenance & citation analysis
- **Can retrieval cite the source event with identity intact? YES for location, NO for integrity.** Every live semantic record carries its source event ID (`source_event_id` in Qdrant payloads; `source_event_id` column in `knowledge_nodes`; `evidence:[source_event_id]` in HybridSearch results). A consumer can name the exact `ping_events` row.
- **But the integrity half of provenance is broken:** `canonical_hash` — the field `EvidenceAuthority.verify()` uses to prove the projection matches the source — is null on 94% of live Qdrant points because `projectToQdrant` sources it from `event.metadata.canonical_hash`, which the emitter never populates (only 25/389 points have one). Result: verification **fails closed on the entire live semantic corpus** (`verified:false`, `rejected++`). The design is honest (fail-closed, typed checks: hash/lineage/namespace/backingEvent); the data starves it.
- KnowledgeGraph nodes preserve `confidence` as NULL when the producer supplied none (null-preserving contract, documented in `knowledge_graph.js:1-32`) and record `confidence_provenance` — good provenance hygiene. But `status` promotion never happens, so consumers cannot distinguish "assessed" from "unassessed" beyond the null.

## Staleness & rebuild analysis
- **What updates the semantic layer when source truth changes?** For Qdrant: re-emission of the same event type with the same `event_id` would upsert idempotently — but journal events are immutable and updates arrive as NEW events with NEW IDs → **new point, old point never removed**. `QdrantAdapter` has **no delete method** (`qdrant_adapter.js:8-76`: `_fetch`, `ensureCollection`, `upsert`, `search`, `health` only) and nothing on the live path calls delete on `knowledge`. **Stale-point accumulation is structural.**
- For KnowledgeGraph: `addNode … ON CONFLICT (node_id) DO UPDATE SET data/namespace/status…` — same-content re-projection refreshes; genuinely new state arrives as new nodes. No automatic invalidation of superseded nodes; `updateNodeBySourceEvent` exists but only the (starved) promoter calls it.
- **Drift detection:** none scheduled on the live path. `projected_at` is **hardcoded `null`** (`embedding_service.js` `projectToQdrant`), so there is not even a temporal signal to build staleness queries on. → Proposed minimal patch (see `../patches/agent14-semantic/`).
- **Fallback-vector rot:** 187/389 points are PRNG noise from Ollama outages; no sweep re-embeds them when Ollama recovers. They are down-ranked ×0.5 at retrieval but still occupy the index and dilute neighbor sets.
- **Rebuild:** CLAIMED ("Projection layer: Qdrant (rebuildable)" — `create_constitutional_memory_collection.py` docstring) but **no rebuild script, job, or endpoint exists** for `knowledge`. The Python worker's `projection_status` table is rebuild-*capable* by design, but the worker is dormant. Verdict: rebuild is **claimed, not proven**.
