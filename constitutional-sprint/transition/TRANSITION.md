## 2. Adapter section (summary)

- **Digest-bound, event-recorded transitions exist and are real:** Ask `site_patch`/`object_update` (T1) and customize approve (T2) both re-verify digests against current state and journal their transitions. The one-serializer digest law (`payload_hash` == proposal digest) is enforced at sign and verify time (`site-patch.ts:288-318`).
- **But every adapter transition's "authorizer" is demo-grade:** demo-owner mode (explicitly not authentication), unsigned practice cookie, or caller-chosen `actorId`. The adapter never proves canonical executor authorization; it asserts it.
- **Adapter-local second sources:** owner event log (T9) and claim files (T10) are internally consistent (append-only + fold / audit history) but are NOT the journal. They are independently minted relative to canonical state.
- **Two overlay folds, two journals:** T8 (adapter, Ask FYD) reads the demo journal per call; T4 (core, public pages) folds a journal (default main) at regen time. They are independent implementations over different default sources — agreement is by convention, not construction.
- **Patch applied this session (adapter worktree only):** `src/app/api/fyd/customize/route.ts:14-15` — docstring claimed the clear action "Removes an approved directive from the journal"; code appends a compensating `clear_presentation_intent` op (journal is append-only). Corrected to describe the compensating op. Comment-only; exact-match assertion passed; `git diff` shows only the intended hunk plus three sibling-agent hunks (not mine — see §7). `COMMITS CREATED: NONE.`

## 3. Core section (summary)

- **The canonical-spine lane (T5) is the critical finding.** `POST /events` on the deployment gateway accepts unauthenticated canonical events; the only gates are type registration and namespace policy. `FYD_SITE_OVERLAY` is registered, so mutating overlay ops can be journaled by anyone reaching `:8080` and will be folded into public site projections by `dump.py`. The bearer token operators send is never validated. **Proposed patch written, NOT applied:** `~/workspace/constitutional-sprint/patches/transition/gateway-events-canonical-lane-auth.md` (WHY → EVIDENCE → MINIMUM CHANGE → TEST → RESULT).
- **The signed-envelope lane (T6) verifies signatures but not capabilities.** Adapter-side controller/grant checks can be bypassed by direct submission with a valid key.
- **Projection is derived and honest about it** (T4): ordered fold, event provenance attached, atomic writes, digest-verified read seam. But its approval check for presentation intents is a substring match on a demo marker, and it accepts structurally-valid unbound ops.
- **Dormant authorities (T12, T13):** `BusinessActionAuthority`/`EffectAuthority` are implemented but unwired mutable second-sources; `FydSiteAuthority` is a registry declaration with no implementation. Neither may be "completed" by creating a second canonical authority — convergence must pick the journal as the single transition record.
- **Runtime state 2026-09-24:** `:8080` (deployment gateway) healthy; `:18199` (demo gateway) down → T2/T8/T11 fail closed; demo Postgres `:55433` up; Next on `:3100/:3101/:3210`.
