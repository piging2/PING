## Top 3 security risks (ranked)

1. **`src/app/api/kit/webhook/route.ts` — unauthenticated event injection, LIVE.** No signature or shared-secret check (the declared `KIT_WEBHOOK_SECRET` is never consulted by the route). Any party can POST forged Kit-shaped events that are persisted into the HPP event log with subscriber PII. Evidence: route file has no `verify`/`hmac`/`signature`/`timingSafeEqual` references; it calls `logEvent` on any payload containing `event` + `subscriber`.
2. **`src/app/api/resources/download/route.ts` — unauthenticated Kit tagging + reflected open redirect, LIVE.** POST accepts arbitrary `email`/`resourceUrl`, tags any Kit subscriber by email, logs the email into events, and echoes `resourceUrl` back as `downloadUrl` with no allowlist. Evidence: no auth/validation code in the route; `findSubscriberByEmail(email)` + `applyGuideDownloadTag` on untrusted input.
3. **`src/fyd/owner-mode/gate.ts` + claim/customize/override mutation routes — demo identity is the only authorization, DORMANT-by-design but highest misconfiguration consequence.** The private-network gate reads the client-controlled `Host` header (`customize/route.ts:54`, `overrides/route.ts:118`), and the demo flag is a build-time `NEXT_PUBLIC_*` var. On Vercel the Host is routing-constrained (practical spoof resistance), but the whole owner-mutation surface (customize approve, `owner.correct-fact`, claim verify) collapses to a single env flag. If that flag is ever enabled in a production build, there is no second factor.

## Recommended follow-ups (for the coordinator, not remediated per read-only scope)

- Verify the Kit webhook against Kit's actual webhook signing (or gate it behind a shared secret) before any production traffic; audit the event log for forged events.
- Allowlist `resourceUrl` in the download route (or stop reflecting it); add email format validation.
- Consider deriving the private-host check from connection info or `x-forwarded-host` validation rather than the raw `Host` header, and add a build/deploy assertion that `NEXT_PUBLIC_FYD_DEMO_OWNER_MODE` is unset in production builds.
- Remove or time-box the `diagnostics/sharp` endpoint; switch its token compare to `timingSafeEqual`.
