## EXECUTIVE SYNTHESIS

The single most important new fact of this audit: **the Oracle redeploy is not merely incidentally blocked, it is constitutionally blocked.** The canonical event journal on Oracle is guarded by an append-only trigger that exists in no repository, names no owner, documents no exception path, and rejects the certified migration's `UPDATE` on every boot attempt, forever, until either the trigger policy or the migration changes. No one can authorize a fix because no one is named to authorize it. This is not a bug to patch; it is a governance hole under a constitutional enforcement mechanism.

Everything else in this audit rhymes with that fact. The through-line across all seven lanes:

1. **Gates whose names claim more than their mechanisms execute.** The smoke test stops before the database spine, so it cannot see the migration that kills deploys. "CERTIFIED 189/189" certifies module membership only; the doctrine's own required field (migration/schema compatibility) has no producer at all. The recovery loop's "Postgres recovery" label misattributes deterministic migration failures to database unavailability. Integration health reports "healthy" for integrations with no credentials configured. In each case the gate is not wrong about what it checked; it is wrong about what its name promises.
2. **Failures converted into confident-looking states.** The recovery loop retries a deterministic failure silently and indefinitely. Replay reports `verified:true` from synthetic envelope reconstructions that never read the persisted journal. A lost event on sequence collision is returned to the caller as success. `MAX(sequence)+1` is presented as an allocator. An undrainable cursor is presented as "unprocessed." Each is individually small; together they are a pattern of absent failure semantics at persistence boundaries.
3. **Two eras described by one law.** The standing laws ("PostgreSQL sequence = authoritative ordering," "zero UPDATEs repo-wide," "UnifiedEventRuntime = sole authority") are true of the certified worktree and false of the running system, or contradicted by the certified worktree's own migration. The identity cutover re-mints every event ID, so it is an identity-era migration, not a path swap, and no cross-era dedup plan exists. Until cutover completes, every recovery and replay claim must be era-qualified.
4. **Enforcement without owners.** The append-only trigger has no owner. The tenant privacy boundary ("namespace = privacy boundary") is a comment, not an enforcement: there is no agent-to-tenant binding anywhere, tenant is caller-asserted at every layer, and the two tenant registries are disconnected. The provider-binding decision that would unlock five expansion opportunities sits with no named decider (empirically investigable first, then a genuine decision).
5. **The product loop runs but does not learn.** 144 missions completed, 18 full intelligence chains, zero non-test consumers of mission results, zero approvals through the already-wired KnowledgePromoter path, and outreach learnings with no deterministic consumer. The execution engine works; the learning edges are dead.

The most leveraged near-term work is not new capability but closing these loops: a migration-vs-trigger pre-promotion gate, fail-loud failure states at persistence boundaries, era-qualified operational claims, a named owner for the append-only policy, and the single provider-binding decision that unblocks the expansion backlog.

NEXT: define canonical event-identity bytes once (sorted-keys JSON, explicit float/Unicode rules), implement in JS, add a Python reference implementation, prove sha256 equality on a fixture corpus. Do not change the live hash until proven.

**RTC-002 - Three timestamp authorities write to the same store with no documented reader precedence.** SEVERITY MEDIUM. CLAIM: `ping_events.timestamp` = JS wall clock (`constitutionalTimeAuthority.nowAsISOString()`, UER:130); column DDL default is `NOW()` (PG clock for writers that omit it); `repository_events`/`witnesses`/`certificates` use `NOW()`; Python producers embed their own UTC `at` inside the payload. Readers (`ORDER BY timestamp DESC`) silently pick one clock. The "receipt vs acceptance timestamp" distinction exists physically (`created_at` vs `timestamp`) but no contract tells a cross-runtime reader which is authoritative for ordering. NEXT: read-only inventory of every writer of each timestamp-bearing column; publish the precedence table.

**RTC-003 - Qdrant address split-brain: `QDRANT_URL` vs `QDRANT_HOST`, plus a cross-stack fallback default.** SEVERITY MEDIUM. ## CROSS-DOMAIN PATTERNS

**P1. Names overclaim mechanisms.** Smoke, CERTIFIED, "Postgres recovery," "healthy" integrations, hardcoded-healthy component checks, hybrid search that is keyword search, `verified:true` replay from synthetic envelopes, "sequence" ordering on a system that orders by wall-clock, "privacy boundary" namespaces with no enforcement. The fix in every case is small and local; the cost of not fixing is operator misreasoning at exactly the moment it matters (an outage, a deploy, a cutover).

**P2. Failures become confident states.** Infinite silent retry; dropped inserts returned as success; MAX()+1 returned as an allocator; undrainable cursors returned as "unprocessed"; envelope replay attested as history replay. Each violates PING law 11 in the same shape: the boundary between "nothing exists," "the system failed," and "the system deterministically cannot" is collapsed to one green surface.

**P3. The certified artifact contradicts its own ledger.** AUTH-008 (migration UPDATE vs C-R3's zero-UPDATEs premise), AUTH-009 (backfill MAX+1 vs the no-MAX+1 contract), AUTH-010 (recurring startup writer vs one-shot migration framing). The convergence program's evidence discipline is real, but its documents lag its code. The documents are what the next auditor will trust.

**P4. Era confusion is the default.** Identity (F1/AUTH-011), ordering (N5/AUTH-014), redelivery (F2/AUTH-012), replay (F4), sequence machinery (present in ERA-C, absent in ERA-R). Every operational claim must be era-qualified until cutover completes; the standing laws currently are not.

**P5. Enforcement without owners.** The append-only trigger (AUTH-007), the provider-binding decision, the tenant authority model (TEN-001), the replay "verified" vocabulary (F4). Each is a question evidence cannot answer that currently has nobody named to answer it.

**P6. The product loop executes but does not learn; the outreach machine has the patterns the runtime lacks.** 144 missions with no learning edge; approval path wired with no approvals; outreach's fail-closed imports, typed gate exits, and orphan recovery are proven patterns the runtime's gate work should import rather than re-derive.

**P7. Two tenant stores, two event identity schemes, three timestamp authorities, two registries of everything.** Dedup, identity, canonicalization, validation, projection, retry, evidence, and acceptance are each independently implemented in multiple domains (ergonomics cross-domain finding). The opportunity is usually a shared contract or mechanism, not forced semantic unification; see RTC-001 and TEN-002.
