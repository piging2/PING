### 1c. What "capability" means per layer (do not mix)

- **PING plane (C-01 to C-11):** capabilities are gateway/container enforced. Capability vocabulary that canonically exists: the exterior verb set (C-02) and the delegation issuance (C-03). There is **no canonical capability vocabulary for UI operations** (mission cancel, approval grant, quarantine lift, replay dispatch, dead-letter retry). Enforcement for those today is Bearer auth + namespace syntax + authority dispatch, not named capability grants. Every such name in the matrix below is marked PROPOSED with its reason.
- **Pig substrate (D-01, D-02):** capabilities are discovery projections over driver scripts. A UI rendering them must label them as projections with health scores, never as grants.
- **Resilience program (D-03):** recovery budgets are the governing rule for pass-level recovery; they constrain recovery attempts only and never authorize exceeding caps, shortening pacing, or pushing through warnings.

## 3. Typed clients

### 3a. PublicPingClient (read-only by construction)

The type surface contains only query constructors. There are no POST/PATCH/DELETE builders, no mutation request types, no approval/retry/lift/dispatch constructors. It is incapable of expressing operator mutations, not merely hiding them: a call site cannot construct a write it is not allowed to make, and any forged request still meets the gateway's 401/403 (C-04, C-05).

May express:
- tenant-scoped public projections (homepage sections, maturity labels, receipts) (M-34)
- mission list/detail reads, where the gateway grants them (today event-family reads are 401 without a token per M-10; the client documents intent, the gateway decides)
- public projection reads: /mc/* dashboard reads (M-16), /ops/dashboard and /ops/system with SENSITIVE_PUBLIC handling (M-29)
- promoted knowledge reads only (never candidates or PENDING_HUMAN revisions) (M-25, scoped)
- tenant public configuration (tenant-config tagline/operator/business) (M-27, scoped to public fields)
- every return carries the maturity block (section 4)

May not express: event emission, mission creation, observation emission, approval grant/deny, quarantine lift, dead-letter retry, replay dispatch, capability invocation, tenant writes, namespace policy reads.

### 3b. AuthenticatedPingClient (extends PublicPingClient reads)

Adds the authenticated write vocabulary, each still gated by gateway enforcement (Bearer + namespace syntax today; per-principal ACL once G-1 closes):

- event emission within a namespace (M-12); namespace syntax validated, entitlement NOT yet enforced (P0 Remaining item 1, gap G-1)
- mission creation (M-4); may create replay-dispatch missions (the proven M-35 path), since POST /missions is auth'd
- observation emission after the verification gate (M-13): the client may construct the emission only with a verified-transition receipt from `mark-verified.sh`; unverified research is never promoted (A-14 rule)
- knowledge.search and event.search via the C-02 capability verbs where granted by C-01

May not express: approval grant/deny (M-20), quarantine lift (M-24), knowledge promote (M-26), tenant writes (M-28), dead-letter retry (M-18). Those constructors exist only on OperatorPingClient.

### 3c. OperatorPingClient (extends AuthenticatedPingClient)

The full vocabulary, still enforced at the gateway; the client adds the human-gated constructors. Every held action records `decided_by` and the named approver; nothing here auto-approves:

- approval grant/deny via promoter dispatch (M-20); revision lifecycle candidate to approved to active (M-26)
- quarantine read/lift (M-23, M-24); lift is a recorded human decision, never automatic (A-12 rule)
- dead-letter read/retry dispatch through the Witness to Replay path (M-17, M-18)
- replay dispatch and replay compare (M-35, M-36)
- run retry dispatch (M-8) once the operation exists
- scheduler state reads (M-22); capability health reads (M-21) once the surface exists
- tenant reads/writes and namespace policy reads (M-27, M-28, M-37) once the ACL gap closes; until then, no claim of per-tenant enforcement
- automation health, campaign, prospect reads (M-31, M-32, M-33) as projections over workspace machinery, labeled as non-canonical (outside the PING intelligence boundary)

Operator identity: Nolan's explicit authorization is the human gate. In code terms this maps to the named-approver pattern already proven (`required_approver: Nolan Geske (human)`, `decided_by: null` until decided).

## 4. Shared schema package

One schema package, shared by all three clients and all surfaces. No surface invents its own Mission or Event shape. Each schema carries the maturity block: `maturity` (Maturity enum), `proof_status` (ProofStatus enum), `verified_at` (ISO timestamp or null), `evidence_ref` (content-addressed reference or capture receipt), `source` (authority or artifact the value was read from). Field terminology follows existing code where it exists (thread-handoffs.md thread 5; audit-table column lists; A-61 edge rules).

- **Mission**: id (deterministic where issued, e.g. sha256 prefix), objective, principal, agent_identity, status (created/assigned/running/completed/failed/archived), parent_mission_id, correlation_id, namespace, attempts, lease state, created_at, updated_at. Source: MissionRuntime over ping_missions; `gateway/routes/mission_control.js:242`, `orchestration.js:56`.
- **Run**: PROPOSED (blocked on run_id instrumentation, gap G-2): id, mission_id, agent, worktree, container/runtime, model_route, capabilities[], started_at, ended_at, status, cost, latency, parent/child links.
- **Execution**: id, run_id, capability, command/tool, input_hash, output_hash, host, runtime, duration, result, failure_class (A-02 vocabulary), artifacts[]. Source terms: `executionReport.status` (execution_runtime.js:102), `capability_requests` columns.
- **Event**: event_id (sha256 over {eventType, source, [namespace], [logical_id|payload]}), event_type, source, namespace, logical_id, payload, correlation_id, ancestors, descendants, created_at. Emit result shape {status:'ok'|'error', eventId}. Source: unified_event_runtime.js emit(); canonical envelope.
- **Artifact**: artifact_id, content_hash, output_refs, raw-bytes pointer (bytes stay in files; hashes+pointers in events, P-05 L3). Append result {success:true, object_id}.
- **Evidence**: observation (statement + source span + confidence), source_evidence (URLs, quotes, timestamps), verification {result: verified/failed/unconfirmable, method, timestamp, verifier}, contradictions[] (preserved, never collapsed), derived claims[]. Edge rule: every relationship edge carries provenance or is classified "inferred" (A-61).
- **Projection**: projection_id, source_authority, derived_at, staleness, query, maturity block. Screens render projections, never source truth directly.
- **Worker**: worker_id, event_types handled, status (idle/monitoring/waiting/executing), runtime (js/python/exterior), last heartbeat.
- **Authority**: name, owned concern, enforcement point, status (per authorities/registry.yaml vocabulary). The one-authority-per-concern map from section 1 of the harvest spec is the seed data.
- **Capability**: two shapes, labeled. PING plane: name (canonical verb from C-02), granted, parameters, authz decision, policy_violation, result, event_id (audit columns). Pig substrate: name, description, strategies[] (name, health, healthScore, lastSuccess, observedCount, confidence, preferred, notes), preferredStrategy (discovery projection D-02 shape).
- **AutomationHealth**: pass_class (ten A-02 classes), funnel stages (discovered/eligible/selected/attempted/succeeded/verified/failed; A-05), gap states (NOT_REQUIRED/NOT_RUN/SKIPPED/FAILED/BLOCKED/NO_VALUE/DEGRADED; A-65), intent states (EXECUTED/FAILED/NOT_ATTEMPTED/UNKNOWN_EXECUTION; A-09), quarantine records, cadence state (A-70).
- **Approval**: node_id, kind (proposal/revision), status (candidate/PENDING_HUMAN/approved/rejected), required_approver, decided_by, decided_at, evidence cited, confidence.
- **Quarantine**: quarantined_at, approved_by, reason, consecutive_failures, retry_budget, attempts[] (artifacts/errors/timestamps preserved).
- **Campaign**: goal, audience segments, intent, agents, content, channels, actions, results, evidence refs, next strategy (A-17 loop; labeled non-canonical until backed by gateway events).
- **Prospect**: identity columns + intelligence columns (A-26), priority_state (HOT/WARM/WATCH/SUPPRESS), suppression_state, stack grades (CONFIRMED/STRONG INDICATION/WEAK INDICATION/UNKNOWN).
- **Tenant**: tenant_id, tenant-config (tagline/operator/business), namespace bindings, isolation proof (PROPOSED: required before any enforcement claim).
- **Identity**: agent_id, agent_name, principal, tier (L1 "Observe" / L2 "Workspace Write"; name-only at the middleware layer today).
- **Namespace**: name, syntax rules; entitlement map PROPOSED (gap G-1).
- **Correlation**: correlation_id, ancestors[], descendants[] (P-05 L2 causal tree).
- **Maturity**: PROVEN | BUILT_NOT_LIVE | EXPERIMENTAL | DIRECTION | UNPROVEN | FALSIFIED | UNKNOWN. Site label mapping: Live/Built/Experimental/Direction/Unproven (`TRUTH_MATRIX.md`).
- **ProofStatus**: VERIFIED_LIVE | CAPTURED | SELF_TESTED | ASSERTED | NONE. `evidence_ref` is required for every value except NONE.
- **Error**: code, message, classification (A-02 pass class or deterministic failure envelope vocabulary), remediation, retryable flag, evidence links (never a bare "error rate high"; X-30 anti-pattern refused).
- **Pagination**: cursor/page, limit, total, has_more.

## 5. Projection rules

1. **Screens are projections; there is one data model per concern.** The Mission list, the Run timeline, and the Evidence view all read the same authorities (ping_missions, ping_events, knowledge graph). No surface invents a competing Mission or Event shape. (Harvest spec sec 14.)
2. **Fail-closed rendering.** A level that cannot be read renders Unavailable/UNKNOWN, never 0 or "All clear". A pass that produced no evidence is SUSPECT, not successful (A-02 rule). (Harvest spec secs 4, 5, 15.)
3. **UI CLAIM <= BACKEND PROOF.** Every rendered claim carries the maturity block (maturity, proof_status, verified_at, evidence_ref, source). A claim may never exceed the highest proven rung of the proof ladder: EXISTS, IMPORTS, REACHABLE, EXECUTES, PERSISTS, PRODUCES EVIDENCE, REPLAYS, REPRODUCES, CERTIFIED. (Nolan's standing order; harvest spec sec 15.)
4. **The UI is not a second permission plane.** Visibility is UX only; the gateway enforces. The UI may narrow or defer work but cannot widen an access profile, revive an unavailable capability, or grant permissions. Approvals, retries, and wakes dispatch through MissionRuntime/ExecutionAuthority policy, never around it. (X-21; harvest spec sec 4, sec 13 item 1.)
5. **Public SDK read-only by construction.** The type surface cannot express operator mutations. Hidden buttons, disabled controls, client-side roles, and frontend routing are never authorization.
6. **Tenant scoping rides on namespace.** Per-tenant projections filter by namespace. No surface claims per-tenant enforcement until the namespace ACL gap (G-1) closes and the two-tenant isolation proof (G-11) lands. (Harvest spec sec 11.)
7. **Drill-down preserves context.** The zoom path Mission to Run to Execution to Event to Artifact to Evidence to Projection is always visible as a breadcrumb; context is never lost moving down the chain. Both directions must hold: from "something is wrong" down to the exact evidence, and from a strategic goal down to the missions advancing it. (Harvest spec sec 14.)
8. **Live runtime queue and tracked work board stay visually distinct** at every zoom level; one list mixing "currently executing" with "planned" lies about both. (X-25; harvest spec sec 4.)
9. **Public frontend framing.** HPP is frozen; the public frontend is a BUILT_NOT_LIVE tenant/product projection in an independent repo. It is never described as an HPP transformation. (Memory: PING website section.)
