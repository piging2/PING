Dedicated Instagram engagement pass for PING Social outreach (Nolan's 2026-09-13 instruction: run engagement passes every few hours, maximum sustainable volume).

STAY-ON RULE (2026-09-14, Nolan's standing directive): this schedule stays ENABLED unless there is a real blocker or a genuine flagged-account risk. A logged-out session, a failed login restore, Pig unreachable, or CDP down are NOT reasons to disable: end the run with zero engagement, log it, and let the next pass retry. Disable only on: an actual account restriction, action block, checkpoint, or verification challenge that signals the account is flagged (then halve next pass's caps per step 8 and surface it to Nolan immediately), or Nolan shutting off the Pig. Never disable for routine auth/infra hiccups.

MECHANICAL NEVER-RE-ENGAGE (2026-09-14): prose is not the enforcement. The guard script ~/workspace/outreach/engagement-guard.py consults the durable history in ~/workspace/outreach/instagram-engagement.md. The steps below are mandatory; an LLM that forgets the rule still cannot engage a blocked account.

Steps:
1. Read ~/workspace/outreach/instagram-engagement.md header rules first.
2. Phase A, discovery only: spawn a browser task for Instagram as nolanpigi (verify signed in first; restore saved session if logged out; if login cannot be restored, stop with zero engagement, log it, keep the schedule enabled). The task is READ-ONLY: find Western Colorado home-service trade business accounts with eligible public feed posts, and return candidate handles plus post URLs. It must NOT like, comment, follow, or DM anything. Business accounts only, never personal profiles.
3. Write the returned candidates to ~/workspace/goals/ping-social-outreach-campaign/hidden_files/engagement-passes/ig-candidates-<timestamp>.json as [{"account":"@handle","url":"https://www.instagram.com/p/.../"}, ...].
4. Run the guard: `~/workspace/outreach/engagement-guard.py filter --platform instagram --in <candidates file> --out <eligible file> --audit`. It consults the durable history and classifies each candidate ELIGIBLE / ALREADY_ENGAGED / BLOCKED / UNKNOWN-UNCHECKABLE. Only ELIGIBLE candidates go in the eligible file; the rest are logged as SKIPPED_REENGAGEMENT or BLOCKED with reasons. If the guard exits 3 (history uncheckable), FAIL CLOSED: end the pass with zero engagement, log the fail-closed, keep the schedule enabled. If zero candidates are eligible, log it and end the pass quietly.
4b. Unknown-execution filter: run `~/workspace/outreach/action-intent-ledger.py refuse --platform instagram --in <eligible file> --out <final file> --pass-id ig-<timestamp>` using the same <timestamp> as the candidates file. It refuses any candidate whose account has an unresolved intent from an older pass (a previous worker died between intent and outcome) with a truthful UNKNOWN_EXECUTION reason, never silently skipping. If it exits 3 (ledger unreadable), FAIL CLOSED: end the pass with zero engagement and log it. If zero candidates remain, log it and end quietly. Copy refused UNKNOWN_EXECUTION entries into the pass log section; they need explicit reconciliation, not a retry.
5. Phase B, engagement only: first write the closed action set to ~/workspace/goals/ping-social-outreach-campaign/hidden_files/engagement-passes/ig-actions-<timestamp>.json as [{"account":"@handle","url":"https://www.instagram.com/p/.../","action":"like|comment"}, ...], assigning each final candidate its planned action within the caps below.
5a. Capability gate (automation-resilience program, 2026-09-17): BEFORE writing any intents, check ~/workspace/pig-fb/ig-capability-state.json (the sanctioned reader is ~/workspace/pig-fb/ig-capability-gate.sh; the Pig runners enforce the same gate themselves, but check here first so a blocked run never leaves dangling intents): if status=BLOCKED (currently BROWSER_WEDGE on the Pig's ig-profile Chrome), end the pass immediately with classification DEPENDENCY_FAILURE, write NO intents and hand NO actions to any browser task, log it in ~/workspace/outreach/instagram-engagement.md, keep the schedule enabled, and stay quiet. Never fire browser work into a wedged browser; never attempt to restart, kill, or relaunch the ig-profile Chrome (the 2026-09-16 force-kill lost the IG session). Recovery is Nolan's manual close/reopen, verified by ~/workspace/pig-fb/ig-recovery-test.sh.
5a2. Probe gate (2026-09-18, approved probe policy; NO separate probe scheduler exists by program order). While the gate in 5a reports BLOCKED, run `~/workspace/pig-fb/blocked-capability-probe.sh` FIRST, before any other pass work. The script is the probe implementation: it self-defers with classification PROBE_DEFERRED when last_probe is within 6h (effective probe cadence ~6h from this 2h pass, no new scheduling machinery), otherwise it runs one lightweight read-only CDP probe (connectOverCDP :9226, 20s timeout, no navigation, no actions) and records last_probe, probe_result, consecutive_failures, and derived next_probe in ~/workspace/pig-fb/ig-capability-state.json plus an evidence line in the probes log. It NEVER restarts, kills, or force-closes the ig-profile Chrome. After the probe, re-read the gate: if status is now AVAILABLE (ig-recovery-test.sh, the exclusive unlock writer, flipped it after a RECOVERY_DETECTED probe), continue this pass normally. Otherwise end the pass immediately with the probe outcome classification (WEDGE_PERSISTS, PROBE_DEFERRED, or INCONCLUSIVE_PIG_UNREACHABLE): log one line in ~/workspace/outreach/instagram-engagement.md, attempt NO engagement, keep the schedule enabled, stay quiet. Never run a full engagement pass while BLOCKED.
5b. Canary (2026-09-17): when the capability state carries canary_required=true (set automatically by ig-recovery-test.sh when the wedge clears), the browser driver runs with CANARY_REQUIRED=1 (env or job field; both Pig drivers ig-engage.js and ig-unfollow.js honor it): the driver executes the FIRST action as a canary, verifies the result, and only then continues the batch; a failed canary halts the run. The flag clears automatically after a verified canary. No manual step.
5c. Intent before action: BEFORE Phase B starts, run `~/workspace/outreach/action-intent-ledger.py write-intents --platform instagram --in <ig-actions file> --pass-id ig-<timestamp>`. One intent record per planned action, stage ACTION_INTENT_DURABLE, durable before any browser action. If this fails, do not start Phase B. The pass_id is ig-<candidates timestamp> for the whole pass; reuse it across restarts of the same pass (a new pass_id means a new pass, and other passes' unresolved intents block). When the Phase B browser task starts (the actions are handed to it), run `~/workspace/outreach/action-intent-ledger.py mark-execution --platform instagram --pass-id ig-<timestamp>`: from this point a missing observation means UNKNOWN_EXECUTION, never a silent retry. Mark BEFORE the task starts so a crash between marking and start still fails closed. Then spawn the second browser task with the ig-actions file as its CLOSED action set: it may execute ONLY the planned actions listed, up to the caps, and nothing else. If it cannot read the file, it does nothing. No new discovery in this phase.
6. Restart safety: after every batch of ~5 completed actions (and on any restart before the pass completes), call `~/workspace/outreach/engagement-guard.py record --platform instagram --account <handle> --url <post url> --action like|comment` for each completed action, so the durable log reflects reality immediately. Also record each batch's outcomes in the intent ledger: `~/workspace/outreach/action-intent-ledger.py record-outcomes --platform instagram --pass-id ig-<timestamp> --outcomes-json <batch report>` where the batch report is [{"account":"@handle","url":"...","action":"like|comment","ok":true/false,"note":"..."}]. Outcomes close intents as OBSERVATION with terminal EXECUTED (ok=true), FAILED (ok=false), or NOT_ATTEMPTED (worker proves it never acted); a crash between intent and observation leaves EXECUTION-stage intents UNKNOWN_EXECUTION, which the next pass refuses until reconciled (never auto-retried, never silently retried for any external commitment). On restart, re-run steps 4 and 4b on the remaining candidates before continuing.
7. Engagement rules: Western Colorado home-service trade business accounts only (plumbing, HVAC, electrical, roofing, landscaping, garage doors, pest control, etc.). Prefer regular public feed posts (photos, carousels) over reels; only engage a reel if it visibly has public comments already. Volume: up to 50 likes plus up to 12 comments per pass (Nolan's 2026-09-15 heavy directive: maximum sustainable volume inside the safety rails). Human pacing: 60 to 120 seconds between actions. View each post fully before engaging. Never exceed these caps. Parallelism: run ONE browser task per pass on this account; parallelize across platforms, never within a pass (two tasks on the same account would interleave actions and break pacing).
8. Comment voice: under 20 words, funny first, then punchy, expert/techy but down to earth, post-specific. Never sell, never mention PING Social, no links, no contact info, no customer-posing, no em dashes.
9. Stop instantly on any action block, checkpoint, verification challenge, rate-limit warning, or any sign of reduced reach, and report it: a blocked account produces zero metrics, so backing off is the priority over volume. If a warning ever appears, halve the next pass's caps and note it in the log.
10. While engaging, also note discovery: new Western Colorado trade business handles worth prospecting go into ~/workspace/outreach/instagram-prospects.md with a one-line note.
11. Post-pass verification: write the browser task's reported completed actions to a report file and run `~/workspace/outreach/engagement-guard.py verify --platform instagram --report <report file>`. Any VIOLATION (an action that was not ELIGIBLE at selection time) is a real mistake: surface it to Nolan in the final message.
12. Reconciliation is deliberate, never automatic: `~/workspace/outreach/action-intent-ledger.py list-unknown` shows unresolved intents with their evidence; `~/workspace/outreach/action-intent-ledger.py reconcile --intent-id <id> --outcome EXECUTED|NOT_ATTEMPTED --reason <reason> --evidence <evidence> --resolved-by <who>` clears one intent. EXECUTED additionally requires --history-recorded, proving the action is already in the durable engagement log via guard record.

After the pass, append a dated pass section to ~/workspace/outreach/instagram-engagement.md: pass number, likes (handles + post URLs), comments (verbatim text + post URL), skipped accounts and why (including guard-blocked ones), any anomalies. Keep runs quiet: only surface to Nolan in the final message if there was an action block, checkpoint, login failure, guard fail-closed, or a verify VIOLATION; otherwise report only the pass counts.
