## The six programs (parallel fronts)

**PROGRAM A — ONE-CLICK BUSINESS BOOTSTRAP.** URL (+ optional authorized account
connections) -> LIVE FYD BUSINESS: business identity, services/products,
locations, people, projects, media, contact points, hours, social identities,
important relationships, customer actions, website/presence, Ask context,
object profiles, owner control surface, distribution-ready objects. Pipeline:
DISCOVER -> ACQUIRE -> OBSERVE -> EXTRACT -> RESOLVE -> BUILD OBJECT GRAPH ->
DETECT CONFLICTS -> GENERATE PRESENCE -> GENERATE CONCIERGE CONTEXT -> OWNER
REVIEW. Target: paste URL, FYD builds, owner fixes, connect channels, turn on
approved capabilities, go. Every additional setup step is suspect. Measure: URL
-> recognizable business; URL -> owner-ready; URL -> first shareable object;
URL -> first customer interaction; URL -> first useful outcome.

**PROGRAM B — THE SOCIAL OBJECT PROTOCOL.** Build social around objects, not
posts. Every externally usable FYD object exposes where semantically
appropriate: IDENTITY, TYPE, OWNER/TENANT, PUBLIC PRESENTATION, MEDIA,
DESCRIPTION, RELATIONSHIPS, EVIDENCE STATUS, CURRENTNESS, VISIBILITY,
CAPABILITIES, SHARE TARGET, CANONICAL REFERENCE, INTERACTION SEMANTICS. This is
a projection/protocol over the canonical graph — never a second social-object
truth model.

**PROGRAM C — OBJECT UNIQUENESS AND CUSTOMIZATION.** Separate OBJECT TRUTH
(what it is), OBJECT IDENTITY (how recognized), OBJECT PRESENTATION INTENT
(how the owner wants it represented), OBJECT EXPERIENCE (how rendered for this
viewer/channel/context). Progressive support: display name, short identity,
logo/avatar, cover/hero, visual emphasis, description, featured facts,
featured relationships, featured capability, visibility, ordering,
presentation style, channel-specific projection intent. Owner intent ("Make
this my featured service", "Don't show this person publicly") converts into
structured durable presentation state. No React editing. No customer
conditional. No truth mutation disguised as styling.

**PROGRAM D — FYD-NATIVE SOCIAL GRAPH.** Portable relationships first, not a
feed clone: PERSON FOLLOWS BUSINESS, PERSON FOLLOWS PERSON, BUSINESS
ASSOCIATED_WITH PERSON, BUSINESS OFFERS SERVICE, PROJECT PERFORMED_BY BUSINESS,
PROJECT USES/REFERENCES SERVICE, OBJECT REFERENCES OBJECT, PERSON SAVES
OBJECT, recommendations/referrals only where semantics and policy are defined.
Each relationship has identity, source, visibility, authorization, time, state,
provenance. FYD-native semantics stay canonical; external networks are
projections/actions. Never pretend every provider's follow/like/friend mean the
same thing.

**PROGRAM E — ALWAYS-ON AGENT MARKETING.** Architecture: BUSINESS GOAL ->
OPPORTUNITY -> AUDIENCE -> OBJECTS -> EVIDENCE -> HYPOTHESIS ->
CONTENT/INTERACTION PLAN -> CHANNEL CAPABILITIES -> POLICY -> APPROVAL WHERE
REQUIRED -> EXECUTION -> RECEIPTS -> RESPONSES -> OUTCOMES -> LEARNING.
Continuous evidence-backed opportunity discovery (new project, seasonal
relevance, question clusters, poorly represented service, new media, info
change, attention anomalies, relevant external conversation, owner news, FAQ
gap) — not continuous posting. Propose/execute per capability and policy.

**PROGRAM F — MASS INTERACTION INTELLIGENCE.** Build the MASS INTERACTION
COMPILER: natural objective -> TARGET SET -> RESOLUTION -> ELIGIBILITY ->
POLICY -> PRIORITY -> ACTION PLAN -> PREVIEW/APPROVAL IF REQUIRED -> BOUNDED
EXECUTION -> PER-TARGET RECEIPT -> OUTCOME. AI handles ambiguity, semantic
relevance, classification, drafting, novel situations. Deterministic machinery
handles dedup, caps, cooldowns, rate limits, provider state, idempotency,
receipts, retries, HOLD/UNKNOWN, batch execution, audit. HARD INVARIANT: mass
interaction must not become mass spam. Optimize RELEVANCE, RECIPROCITY,
CUSTOMER VALUE, BUSINESS VALUE, RELATIONSHIP QUALITY, OUTCOME — never
interaction counts (those are capacity measurements). Willing to perform zero
interactions when there is nothing useful to do. Build INTERACTION INTELLIGENCE
(who/what, why relevant, relationship, prior interactions, what business
legitimately knows, channel semantics, supported/authorized actions,
repetition risk, outcome value, already done?) choosing IGNORE / OBSERVE /
FOLLOW / REACT / REPLY / SHARE+REFERENCE / ASK / INVITE / ESCALATE. Build
INTERACTION MEMORY: minimum semantic interaction/outcome state to prevent
repeated generic replies, duplicate follows, contradictory messages,
over-engagement, forgotten conversations, stale engagement, double responses,
answered questions, repeated promotion — but not a giant shadow CRM.
PERSONALITY BELONGS TO THE OBJECT/OWNER, NOT THE MODEL: capture
owner-authorized communication intent (voice, formality, brevity, humor,
technical depth, terminology, topics, local character, CTA preference, visual
character, interaction boundaries) while keeping FACT separate from VOICE
separate from STRATEGY. A playful tone never permits invented facts.

**Shareable doorways + object controls + campaigns.** ONE GRAPH, MANY
PROJECTIONS: every public object (Service, Project, ...) becomes website
section, share link, social card, Ask context, search result, campaign target,
QR destination, agent resource — same object, not copies. Owner controls per
object: PUBLIC/PRIVATE, FEATURE/NORMAL/HIDDEN, ALLOW ASK/SHARE/PROMOTION/
INTERACTION, ALLOWED CHANNELS, PRIMARY MEDIA, PRESENTATION INTENT, OWNER
NOTES/CONSTRAINTS, CAPABILITIES — compiled downward, never parallel
authorization machinery. Campaigns are compiled object strategies: GOAL,
TARGET OBJECTS, AUDIENCE, HYPOTHESIS, CHANNELS, CAPABILITIES, BUDGET, POLICY,
CONTENT, INTERACTIONS, OUTCOMES.
