## 3. Strongest candidates

### Strongest MC backend: the mission-control repo (Python) + ping `/api/mc/*` routes as its projection layer
Why: it is the only place that owns the mission lifecycle MODEL (MissionIntent front door with the validate->authorize->dispatch->observe contract, the MC_* event vocabulary in emit.py with content-derived IDs and duplicate-refusal, the canonical ApprovalRequest primitive on branch `p0/approval`, payload lifecycle, ~40 branches of MC iteration, tests). The TypeScript routes are a serving projection: they read the journal and render it, and they own no mission state of their own. Caveats from evidence: (a) the TS serving layer is currently a dirty, partly-untracked tree (agents/approvals/graph/object/search/trace-forward untracked; dispatch/missions modified) — commit or lose it; (b) per laneB7, the backend has no reconciler (UNKNOWN missions say "IN PROGRESS" with nothing in progress), no HOLD projection, no cost surface, and health probes that read 200-OK while ignoring degraded bodies. Strongest does not mean finished.

### Strongest MC frontend: `src/app/mission-control/page.tsx`
Why: it is the only frontend wired to the current backend (7 tabs over the live routes), it enforces the claim-badge law (UI CLAIM <= BACKEND PROOF, every field labeled PROVEN..UNWIRED), it exposes evidence drill paths (mission -> events -> artifacts with sha256 + present flags, digests instead of raw prompts), and it honestly labels prototypes instead of inventing data. The old CockpitDashboard extracts (phase24-ui, uilane-patch) are dead, gateway-client-era artifacts with weaker truth semantics — archive, do not revive.

### Convergence note (matrix input)
The single-object invariant ("change ONE OBJECT and watch Mission Control, FYD website, Ask FYD, search, Circle converge") is best served by: journal (fyd-journal-gateway/events.jsonl) as the event plane, mission-control repo as the mission/approval model, `/api/mc/*` as the projection seam, page.tsx as the operator surface, orca-adapter as the only dispatch path (Gateway ExecutionEngine rejected, orca-cli rejected), and one content-hash event-identity contract. The biggest structural risks to that invariant are the dirty uncommitted MC tree, the two event stores (D9), and the missing reconciler/HOLD projection.
