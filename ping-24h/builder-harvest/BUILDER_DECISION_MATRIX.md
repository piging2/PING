## The single riskiest hardening decision FYD must avoid
Wiring any editor, agent, or canvas to the mutation contract BEFORE unifying the three fragmented patch vocabularies (SiteIntent / SitePatchOperation / OwnerIntent) into ONE canonical op set with durable versions-as-undo. If the fragmented vocabulary hardens, every future mutation source (Puck adapter, chat, API, MCP) will speak a different dialect, the single-mutation-contract principle dies at birth, and FYD gets five years of translation shims instead of one typed patch stream. Secondarily: letting demo-mode trust seams (DEMO OWNER MODE, asserted media authorization, demo journal writes) leak into production semantics. The order is fixed: unify the op vocabulary and versions first, then attach the Puck adapter, then agents.
