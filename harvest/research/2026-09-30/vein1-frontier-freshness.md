## CANDIDATE 1: http-cache-semantics (kornelski)

- **AREA:** Acquisition. Dimension (a): incremental refresh / conditional requests / RFC 7234 freshness evaluation.
- **CURRENT PING IMPLEMENTATION:** None for conditional requests. Every re-acquisition of a URL re-downloads the full body (`safeFetchPage` via the SSRF gate, `safe-fetch.ts`); `evidenceHash` proves what was seen but requires the full fetch to compute. No ETag/Last-Modified storage, no `If-None-Match`/`If-Modified-Since` emission, no freshness-lifetime computation, no 304 handling. (file:line evidence: `static-adapter.ts` builds observations with no validator fields; `safe-fetch.ts` has no conditional-header code.)
- **EXTERNAL IMPLEMENTATION:** `CachePolicy`, a ~928-line single-file zero-dependency JS module (`index.js`) with TypeScript types, implementing RFC 7234 shared/private cache semantics. Traced hot paths at the pinned SHA:
  - Constructor (index.js:160-260): parses Cache-Control from both request and response, records `_responseTime`, `_status`, `_resHeaders`, `_method`, `_url`, `_host`, Vary-selected request headers only (deliberately does not retain all request headers), `ignoreCargoCult` (drops blindly-copied `pre-check`/`post-check`/`no-cache`/`no-store`/`must-revalidate`/`expires`/`pragma` when enabled).
  - `storable()` (index.js:266-300): the full RFC 7234 section 3 store-decision (method in GET/HEAD/(POST with explicit expiration), understood status, no `no-store`, private/auth rules for shared caches, explicit expiration OR public OR cacheable-by-default status).
  - `maxAge()` (index.js:594-660): freshness-lifetime precedence s-maxage (shared) > max-age > Expires (invalid date parsed as already-expired per RFC) > Last-Modified heuristic `(date - lastModified) * _cacheHeuristic` with default 0.1 (RFC 7234 s4.2.2, "10% matches IE") > immutable min TTL (default 24h). Zeroes out when `no-cache` response directive or shared+set-cookie without public.
  - `age()` / `stale()` / `timeToLive()` (index.js:572-664): current age = Age header + resident time; `timeToLive()` folds in `stale-while-revalidate` and `stale-if-error` and is the recommended cache-storage TTL.
  - `evaluateRequest(req)` (index.js:394-445): the complete serve decision returning `{response?, revalidation?}`. Hard rules: `must-revalidate` always bypasses; URL+host+method+Vary match required; request `no-cache` pragma/directive bypasses; `max-age`/`min-fresh`/`max-stale` request directives honored; stale served only with `max-stale` allowance or `stale-while-revalidate` (the latter triggers ASYNCHRONOUS revalidation, `synchronous: false`).
  - `revalidationHeaders(incomingReq)` (index.js:758-807): builds conditional headers from stored validators. If-None-Match APPEND semantics (incoming `if-none-match, <stored etag>`), If-Modified-Since from stored Last-Modified; strips `if-range`; removes weak validators when method is not GET or range/conditional headers present (RFC 7232: weak validators MUST NOT be used in non-GET validation); deletes both validators when the request does not match the cached entry or the entry was not storable.
  - `revalidatedPolicy(request, response)` (index.js:832-928): the 304 merge law. `modified: false` when the validator still matches (strong-strong, weak-weak, or Last-Modified equality); on match, non-excluded 304 headers replace stored headers and a fresh policy is constructed with the same body reuse. On mismatch, constructs a policy for the new response with `modified: true`. Handles `stale-if-error` by reusing the policy on error responses.
  - `toObject()` / `fromObject()` (index.js:700-757): versioned (`v: 1`) serializable policy state, persistence-ready.
- **EXACT REPO + SHA:** `kornelski/http-cache-semantics`, `f01112e954b83cfa8765b633ba880e5e980aa54c` (full 40-char). Verified live via GitHub commits API 2026-09-30: this is the current `main` HEAD (commit "Declare types", 2025-03-19). Clone made to `~/workspace/harvest/research/2026-09-30/http-cache-semantics`.
- **LICENSE:** BSD-2-Clause (GitHub license endpoint `spdx_id: BSD-2-Clause`; `package.json` `"license": "BSD-2-Clause"`; root `LICENSE` file present). No file-level exceptions found (single distributable file, `index.js`). Permissive: port or DEPEND both allowed. No copyleft, no network-copyleft, no patent clause beyond the standard BSD disclaimer, no attribution burden beyond retaining the copyright notice.
- **MECHANISM WORTH HARVESTING:** (1) the freshness-lifetime precedence math (`maxAge` + `age` + `stale` + `timeToLive`); (2) `revalidationHeaders` conditional-header construction rules (ETag append semantics, weak-validator stripping); (3) the 304-merge law (`revalidatedPolicy` validator matching); (4) the versioned serializable policy object; (5) the `ignoreCargoCult` pragmatic override option.
- **WHY IT IS BETTER:** PING currently pays a full-body download on every re-acquisition to learn whether anything changed. These laws let a refresh pass (1) skip re-fetch entirely while `timeToLive() > 0`, and (2) revalidate with conditional headers so an unchanged page costs a 304 header round-trip instead of the full body. For the FYD URL -> ACQUISITION arrow, which re-observes business websites on refresh, this is bandwidth, politeness, and latency all at once, with zero semantic risk because the mechanism only decides WHEN to fetch, never WHAT the evidence says.
- **WHAT NOT TO COPY:** The shared-cache machinery is irrelevant (PING is not a shared HTTP cache serving third-party clients): `_isShared`, `s-maxage`, `proxy-revalidate`, the `113` heuristic warning injection, `Age` header rewriting. `evaluateRequest`'s client-serving branch is not needed; PING needs only the client-side freshness check + revalidation. Do not adopt the npm package as a runtime request cache that answers ACQUISITION with stored bodies (that would be a new authority over evidence freshness and would collide with the append-only observation model).
- **PING AUTHORITY IT MUST REMAIN UNDER:** ObservationAuthority (and the SSRF/egress gate, `safe-fetch.ts`). Conditional fetch is a transport optimization: it must never invent observations, never serve stale bytes as current evidence, and never alter `evidenceHash` semantics. Every fetch event, including 304s, remains recorded as an observation event.
- **MINIMAL PATCH:** None authorized now (no proven defect). The future patch shape, if a refresh loop exists: extend `AcquiredObservation` with optional `validators: { etag?: string; lastModified?: string; date?: string; cachePolicyState?: <serialized> }`, store them alongside the observation; on re-acquire, call `timeToLive()` on the restored policy to skip or `revalidationHeaders()` to revalidate; handle 304 by keeping the old bytes + old `evidenceHash` but recording a new observation event (proves the re-check happened without fabricating evidence). Preference order says DEPEND first: `npm i http-cache-semantics` (single file, zero deps, typed) beats porting ~200 lines of freshness math.
- **EXPECTED DELETION-SIMPLIFICATION:** None now. Later: removes the need for any hand-rolled "did it change" polling heuristic on the refresh path; deletes future ad-hoc ETag handling in `safe-fetch.ts`.
- **TEST THAT PROVES IMPROVEMENT:** A mock-origin test: origin serves ETag on response 1; second request must carry `If-None-Match: <etag>`; origin answers 304; assert (a) no body bytes downloaded, (b) `evidenceHash` equals response-1's hash, (c) an observation event was still recorded for the re-check, (d) a changed-ETag origin answering 200 produces a new hash and a fresh policy. Falsifier: serve a stale `Expires` past date and assert the policy does NOT serve skip (invalid date means already-expired).
- **BENCHMARK IF RELEVANT:** bandwidth-per-refresh on a fixed corpus of business sites (bytes with vs without revalidation); secondary: wall-clock of the refresh pass. No numbers collected this pass; the corpus does not exist yet.
- **SECURITY CONSEQUENCES:** Conditional headers are benign toward the origin. Inverse risk: over-eager freshness would present stale evidence as current, so `maxAge` must be computed against the RESPONSE's directives, never a local default, and a `no-cache` response directive must force revalidation (the donor handles this; any port must preserve it). `revalidatedPolicy` on 304 must not update `evidenceHash` from headers alone; hash changes only when bytes change. ETag as a super-cookie is irrelevant here (server-to-server, no user).
- **MIGRATION-RISK:** Low. Pure functions over header maps; no schema changes until the optional validators field is added; append-only evidence unaffected. New dependency = 1 if DEPEND is chosen.
- **DECISION:** BACKLOG. The laws are the correct narrow harvest for the refresh path and the donor is permissive, zero-dep, and typed. Gated on the 12-question gate: no concrete live failure yet (no refresh loop runs today; single-page intake dominates). The Crawl4AI CacheValidator row covers validator storage; this row covers validator DECISION math. When a refresh defect is proven (a real tenant loop where re-fetch bandwidth or origin politeness is measurable), the decision upgrades to DEPEND (npm package) or HARVEST (port the three functions) under ObservationAuthority.

## CANDIDATE 2: scrapy dupefilter + request fingerprint + depth middleware

- **AREA:** Acquisition. Dimension (b): crawl frontier URL deduplication, anti-loop protection, crawl budget / bounded crawling.
- **CURRENT PING IMPLEMENTATION:** No frontier exists, so there is no frontier dedup. The nearest machinery: `DedupCache` + `normalizeFetchKey` (`budgets.ts:100-182`) for repeated single-page fetches (lowercase host, drop default ports, drop fragment; no query-param sorting, no percent-encoding canonicalization, method/body not part of the key); per-page `seen` Set over raw URL strings in `extractLinks` (`static-adapter.ts`); fail-closed `CrawlLedger` budgets. Nothing prevents re-crawling `http://x/?b=2&a=1` vs `http://x/?a=1&b=2` as distinct URLs; nothing bounds depth because nothing traverses links.
- **EXTERNAL IMPLEMENTATION:** Three cooperating mechanisms traced at the pinned SHA:
  1. `RequestFingerprinter` / `fingerprint()` (`scrapy/utils/request.py`): identity = SHA1 over JSON `{method, canonical_url, body_hex, headers}` with sorted keys. `canonicalize_url` (w3lib) normalizes scheme/host case, percent-encoding, default ports, and SORTS query parameters; fragments dropped by default (`keep_fragments=False`, with an explicit headless-browser exception); session/cookie headers EXCLUDED from the fingerprint by default (documented: session ids are noise, not identity); `verbatim_url` meta escape hatch; results memoized per Request in a WeakKeyDictionary keyed by (headers-tuple, keep_fragments, verbatim_url).
  2. `RFPDupeFilter.request_seen` (`scrapy/dupefilters.py`, 176 lines): fingerprint into an in-memory set; optional `requests.seen` persistence in JOBDIR as length-prefixed binary records (2-byte big-endian length + fingerprint) with truncation tolerance on unclean shutdown; first-dupe logging only (`logdupes` flag); `scheduler/enqueued` stats. `BaseDupeFilter` is the no-op seam for disabling.
  3. Enforcement points: `Scheduler.enqueue_request` (`scrapy/core/scheduler.py:383`): `if not request.dont_filter and self.df.request_seen(request)` -> drop + log. Dedupe happens at ENQUEUE, not at download, so the frontier itself stays loop-free. `dont_filter=True` is the deliberate re-fetch escape hatch.
  4. `DepthMiddleware` (`scrapy/spidermiddlewares/depth.py`): `response.meta['depth']` initialized 0; each outgoing request gets `response.meta['depth'] + 1` (with `depth_reset` meta consumed so it cannot leak across domains); `DEPTH_LIMIT` drops (returns None, counts `depth/request_ignored_count`); `DEPTH_PRIORITY` lowers priority by `depth * prio` so the frontier drains breadth-first.
- **EXACT REPO + SHA:** `scrapy/scrapy`, `5d789b24f994bcdfca97c34d976c73739e064849` (full 40-char). Verified live via GitHub commits API 2026-09-30: current `master` HEAD ("Drop the StatsCollector.__getattribute__() shim (#8243)", 2026-09-28). Sparse clone at `~/workspace/harvest/research/2026-09-30/scrapy` (dupefilters.py, utils/request.py, spidermiddlewares/depth.py, core/scheduler.py, settings only).
- **LICENSE:** BSD-3-Clause (root LICENSE; standard). Permissive: pattern study and narrow TS ports allowed. No copyleft.
- **MECHANISM WORTH HARVESTING:** (1) canonical-URL identity law: dedupe on a canonicalized request fingerprint (method + canonical URL + body), not on raw strings; (2) enqueue-time dedupe (the frontier never holds a duplicate, so loops cannot form); (3) depth accounting in request metadata with a hard `DEPTH_LIMIT` drop and depth-decayed priority; (4) the `dont_filter`/`verbatim_url` deliberate-escape-hatch discipline (re-fetch is explicit, never accidental).
- **WHY IT IS BETTER:** PING's `normalizeFetchKey` is a weaker normalization (query order, encoding variants, and default-vs-explicit port differences all slip through), and there is no depth or enqueue-guard concept at all. When L3 discovery is ever authorized, these laws are the difference between a bounded crawl and an infinite loop on a calendar/pagination link graph. Scrapy's design has ~17 years of production crawl behind the same laws.
- **WHAT NOT TO COPY:** The scheduler/disk-queue machinery, Twisted deferreds, JOBDIR persistence format, the `depth_reset` cross-domain nuance is optional, and SHA1 as the hash (PING uses SHA-256 everywhere; identity law says the canonical hash stays SHA-256). Do not port `w3lib.canonicalize_url` wholesale; the WHATWG URL API plus sorted search params covers the needed cases in TS.
- **PING AUTHORITY IT MUST REMAIN UNDER:** ObservationAuthority (acquisition frontier) plus the egress policy (`safe-fetch.ts` gate). A fingerprint must never become an evidence identity (evidence identity stays the content hash); it is a fetch-scheduling key only.
- **MINIMAL PATCH:** None authorized now (no frontier, no defect). The future patch shape when L3 is built: `canonicalFetchKey(url, method)` in `budgets.ts` (WHATWG URL: lowercase host, drop default ports, sort query params, drop fragment, strip trailing-dot hosts) replacing raw-string identity in `extractLinks`'s `seen` set and in `DedupCache`; a `frontierSeen: Set<string>` consulted at enqueue with a `dontFilter` escape; `depth` in the acquisition request metadata with a hard `maxDepth` drop (the type already has `maxDepth`; enforce it in the L3 loop).
- **EXPECTED DELETION-SIMPLIFICATION:** Later: `normalizeFetchKey` gets superseded by the canonical key (one function replaces one); `extractLinks`'s ad-hoc `seen` Set collapses into the frontier dedupe. No deletion now.
- **TEST THAT PROVES IMPROVEMENT:** A synthetic link graph with a 2-cycle (A links B, B links A), query-param permutations of the same URL, and fragment variants: assert the crawl terminates, each canonical URL fetched exactly once, depth limit respected, and `dontFilter: true` still re-fetches on demand. Falsifier: two genuinely distinct resources that canonicalize identically (over-normalization) must be caught by a test that asserts the fingerprint keeps them distinct.
- **BENCHMARK IF RELEVANT:** duplicate-fetch rate on a synthetic graph with cycles and param permutations (0% duplicates expected); frontier memory growth vs pages crawled. No numbers this pass.
- **SECURITY CONSEQUENCES:** Canonicalization bugs fail in two directions: under-normalization wastes fetches (annoyance); over-normalization collapses distinct resources into one fetch (evidence LOSS: the second resource's observations never exist). The port must be conservative: canonicalize only provably-equivalent forms, and keep raw URL strings on the observation for audit. The dedupe set is a scheduling structure, never evidence; a poisoned set entry could suppress a fetch, so if it ever persists it must be checksummed or treated as a cache (misses are safe).
- **MIGRATION-RISK:** Near zero now (pattern only). Later: pure functions, no authority changes, no new dependencies.
- **DECISION:** PATTERN/REFERENCE ONLY. Laws recorded for the future L3 implementation; re-evaluate the moment L3 discovery is authorized (named gap + Nolan's go). No writer, no defect today: PING has no loop because PING has no crawl.
