# Meme Object Schema

The meme layer is a presentation layer over canonical evidence, never a
source of truth. Every meme object follows the five-layer chain:

```
Observation
    |
Evidence / receipt
    |
Business implication
    |
Verified opportunity
    |
Joke / meme
```

Humor is downstream of evidence. If a layer is missing, the object does
not validate and no draft is generated.

## Families

- `MARKETING_CIRCUS`: "We're everywhere" marketing with weak actual
  conversion machinery. Receipt: observed site + tech stack + missing
  booking/chat.
- `SAAS_STACK_GRAVEYARD`: bloated tool stacks that still miss the basics.
  Receipt: observed technology.
- `AGENCY_MAGIC_TRICK`: agency promise vs observable implementation.
  Receipt: before/after evidence.
- `PING_RECEIPT`: one verified competitive observation rendered as
  observation -> implication -> opportunity -> joke. This is the default
  family. Use it unless the object clearly fits one of the other three.

## Object fields

| Field | Required | Notes |
|---|---|---|
| `id` | yes | snake_case, unique |
| `family` | yes | one of the four above |
| `status` | yes | draft / approved / queued / posted |
| `provisional` | yes | true when the evidence is unconfirmed; the joke must then stay explicitly provisional |
| `hedge` | if provisional | exact hedge phrase that must appear in the joke |
| `observation` | yes | one plain sentence, pattern-level, never a named business |
| `receipt` | yes | `evidence` (list), `sources` (list), `grade` (OBSERVED / INFERRED / VERIFIED) |
| `implication` | yes | what the observation means for the business |
| `opportunity` | yes | the verified, deployable opportunity |
| `joke` | yes | `punchline` (required), `alt` (optional) |
| `drafts` | generated | `facebook_post`, `reply`; generated by compose_meme.py, overridable per object |
| `no_named_business` | yes | must be true; validator also scans against business-names.txt |
| `approved_by` | if approved | who approved, and date |

## Hard rules (enforced by the validator)

1. All five layers present and non-empty.
2. No named business anywhere in observation, joke, or drafts. The
   validator scans against `business-names.txt` (drawn from the
   competitive map). Never roast a business by name. Patterns only.
3. Provisional objects must carry an explicit hedge inside the joke.
   Unconfirmed evidence never gets stated as fact, not even in a joke.
4. No em dashes in any public-facing text. Commas and periods do the work.
5. The receipt grade uses the intel grading rule. A joke never upgrades
   the grade of its evidence.
6. An `@` mention is never generated automatically. Tagging a business is
   a human decision, made at approval time, never by the composer.

## Pipeline

```
Research -> verified observation -> opportunity -> content object
    -> platform-specific draft -> human approval -> post/reply
```

`compose_meme.py validate <file>` enforces the schema.
`compose_meme.py draft <id>` renders platform drafts from the object.
`compose_meme.py approve <id>` records human approval (Nolan).
`compose_meme.py promote <id>` moves an approved object into
`meme-queue.json` as a pending queue item for the PING Social queue.
