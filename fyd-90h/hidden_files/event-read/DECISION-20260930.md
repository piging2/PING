# Event-read path decision: UER.query() is the one read boundary

Date: 2026-09-30
Lane: event-read abstraction worker, convergence GO (2026-09-30)
Rule applied: Nolan's ONE RULE, NO THIRD PATH. Default was EventReadAuthority
as the read boundary with UER as the canonical write/admission spine, with the
standing exception: if EventReadAuthority is a useless shim, standardize
directly on UER.query().

## DECISION

Standardize on **UER.query()** (UnifiedEventRuntime read surface: query(),
getChildren(), getDescendants(), getAncestors(), getCorrelationGroup()) as the
single product-facing event-read abstraction. UER remains the canonical
write/admission spine (emit path unchanged). **Do not build an
EventReadAuthority.** The exception clause fired: EventReadAuthority is a
valueless shim by its own documented description, and it exists nowhere as code
on this disk.

## Evidence: EventReadAuthority is a pure-delegation shim with no loadable implementation

Search scope (standing pre-sprint authority-overlap law): the entire repo
including all worktrees. Searched `~/workspace` (main checkout plus
`~/workspace/.worktrees/*`, `~/workspace/track-a/*/replay|work`),
`/home/hatch/worktrees/*`, `/home/hatch/falsify-consequence-55b5d89`,

case), `event_read_authority`, `event-read-authority`, a file named
`*event_read_authority*`, and `class EventReadAuthority`.

   `class EventReadAuthority extends KernelEventReadAuthority { // No
   additional methods needed - pure delegation }`, re-exporting from
   `runtime/kernel/event_read_authority.js` ("PATCH_003: Gateway shim -
   delegates to kernel implementation"). A subclass whose own comment says no
   additional methods are needed adds zero semantics at the gateway layer.
2. **No loadable implementation exists on disk.** Ten untracked, non-live
   files reference it (pig-src and swarm-07/scratch copies of
   `gateway_runtime.js`, a swarm-01 probe output, `caller-adaptation-lane/gateway_adapter.js`,
   a `lanee-staging` test stub, two tenanos `.ts` string literals, two

   "UnifiedEventRuntime (write side)" vs "EventReadAuthority (read side)").
   Every `require()` of the module is dangling: no
   `event_read_authority.js` file exists anywhere in the searched tree, and
   neither does the kernel file it delegates to. None of these files are
   git-tracked; all are snapshots, scratch, staging, probes, or lane
   workspaces. The intended write/read split in the matrix doc is honored by
   this decision (UER stays the write spine; UER.query() is the read
   boundary); what is not built is a separate shim layer to sit between

3. **The tracked convergence inventory agrees.** Item 20 of
   `fyd-90h/hidden_files/mc-component-inventory.md` records it as a "(kernel

   runtime/kernel/event_read_authority.js", and notes "routes use UER.query()

4. **One conflicting signal, reported honestly.** The untracked
   `lanee-staging/test_sec003_005_auth.js` stub (`makeEventReadAuthority()`)

   not on this disk and cannot be verified, tested, or vendored here. If the
   Pig-side kernel implementation is ever harvested, its read models should
   be evaluated against UER's read surface then; that is a harvest decision

5. **The only other live code reference is off-disk.** The 2026-09-19
   runtime manifest lists the shim as "event reads for routes" in the
   `/home/nolan/ping` Pig checkout, which is not part of this repo.

Conclusion: at every layer visible in this repo, EventReadAuthority is a
delegation shim with no implementable substance. Building one here would be a
new architecture wave adding a layer with zero proven semantics. The standing
exception applies. Collapse the read authority into UER.

## Routing rule going forward

Product-facing event reads go through UER's read surface (query() for
filtered newest-first reads; replay() for deterministic certified-sequence
replay; the causal family for lineage). No new read authority, no shim, no
direct `ping_events` SQL outside UER. UER stays the write/admission spine;
reads never consult the validator/governance path (proven by test).

## Follow-ups (not this lane)

1. The gateway `/events/<TYPE>` routes serving FYD readers must be served
   from UER.query()/replay(), not from any parallel store. Wiring lane owns
   this.
2. Read-side tenant scoping: UER.query() has no namespace filter today;
   tenant isolation is enforced at admission (emit). If FYD serves
   multi-tenant reads, the read path needs a namespace constraint. That is a
   product decision for Nolan, not a shim to invent here.
3. The evolved copy's `replay()` (sequence-ordered, cursor-based) is the
   preferred read for ordered projections once the gateway is wired; it adds
   no new authority.
