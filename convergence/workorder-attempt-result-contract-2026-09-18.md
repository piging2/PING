## PART 1: Consolidated execution contract (PROPOSED, harvested from strongest parts)

### 1A. WorkOrder
- Identity: work_order_id = lowercase hex sha256('workorder:' + task_id)[0:16]. Deterministic; re-issue of the same task_id is idempotent. REQUIRED: exactly ONE work-order identity per unit of work (closes F1 below).
- Closed envelope (additionalProperties false), 14 required + 1 optional:
  work_order_id, agent_id, mission_id, task_id, correlation_id, context_pack_id, attempt,
  principal, namespace, capability, input, constraints, result_path, deadline; optional causation_id (string|null).
- principal = constant 'ping:external-agent-adapter', issued never self-asserted.
- namespace matches ^(core|tenant)::[a-z0-9_.-]+$, owned by the canonicalization authority (no local copies).
- capability must be in the executor profile's allowedCapabilities.
- task_id is a stable task key (never run-scoped, never wall-clock/PID derived).
- context_pack_id is an immutable ContextPack identity. Issuance gate: compiler-derived (ContextCompiler._generateContextPackId over missionId/query/namespace/correlationId/retrievalManifest) or registry-verified. Synthetic minted ids are forbidden unless registry-backed (closes F4).
- constraints is an object that may only tighten the profile maxConstraints; must include read_only, allowed_workspace, no_network, no_writes, no_canonical_events, no_mission_state_writes; the last two hard-required true.
- result_path is PING-owned (rendezvous/persistence path). No executor writes it directly.
- deadline is an absolute ISO cutoff, enforced at verification.
- attempt starts at 1, increments per retry; bound into the result identity.
- Authorization (authorizeWorkOrder), fail-closed: deny unknown agent, blockedExternal (time-gated object allowed), PENDING_AUTH status, capability outside allowlist, namespace mismatch, constraints not an object or loosening, missing no_canonical_events/no_mission_state_writes. Returns {granted} or {granted:false, reason}.
- Budget lives OUTSIDE the envelope: durable reservation per work_order_id (idempotent), attempt ceilings, per-run ceilings, all orchestration-side. Executor cost/quota (e.g. Copilot) is resolved at the dispatcher boundary and never enters the envelope.

### 1B. Attempt
- Identity: attempt_id = work_order_id + '-attempt-' + attempt_number (1-based). Recorded BEFORE dispatch (crash window closed by construction). attempt_count and last_attempt_id on the durable work order.
- Lifecycle: DISPATCHING (recorded) -> TRANSPORT_SETTLED (exit code/signal/timedOut/transport error + rendezvous) -> ENVELOPE_EXTRACTED | PROTOCOL_FAILURE -> OUTCOME (ACCEPTED | WORKER_FAILED | VERIFICATION_FAILED | TIMED_OUT-as-failed-envelope).
- Retry binding: same task_id re-issues same work_order_id; the per-attempt copy (wo = {...workOrder, attempt:n}) goes to transport AND to verification; result_id binds (work_order_id, attempt) so retries yield distinct result identities and idempotent emission per attempt.
- Lease/heartbeat (PROPOSED; missing today): attempt lease derived from deadline; dispatcher timeout kills transport (SIGKILL) and records an honest TIMED_OUT failed attempt; coordinator reconciles live rendezvous within a bounded wait; attempt-level heartbeat fields (last_heartbeat_at, stale threshold) mirroring WorkerRuntime worker liveness.
- Timeout envelope rule: on timeout the invoker must not fabricate success; it reports status failed, output null, error non-empty, evidence present with timestamps.

### 1C. ResultEnvelope
- 8 fields, closed: work_order_id, context_pack_id, agent_id, capability, status, output, evidence, error.
- Verification guards (verifyResultEnvelope): all 8 present; exact string echoes of work_order_id/context_pack_id/agent_id/capability against the issued order; authorized agent == invoked agent == result agent; status in {completed, failed}; completed => output non-null AND error null; failed => output null AND error non-empty; evidence is an object; verifiedAt is ISO and <= deadline. Invalid => {valid:false, retryable:false}; can never reach canonical event authority.
- Identity: result_id = sha256('external-result:' + stableStringify({work_order_id, mission_id, task_id, attempt, agent_id, capability, context_pack_id, namespace})) as 64-hex.
- Recording (recordVerifiedResult): verify first, then emit via the INJECTED canonical event runtime: WORKER_COMPLETED | WORKER_FAILED with namespace, logical_id = result_id (idempotent), correlation_id, causation_id. The executor never receives runtime access or event credentials. Event identity stays solely with UnifiedEventRuntime.computeEventId.

### 1D. State machines and exact transition guards
WorkOrder unit lifecycle (harvested from orca_status_model.js; guards: each transition requires the named evidence artifact and the via-function):
  PLANNED --[plan artifact 02-plan.json; via classifyDelegation + authorizeWorkOrder]--> AUTHORIZED
  AUTHORIZED --[workorder-<tag>.json; via issueWorkOrder]--> QUEUED
  QUEUED --[dispatch-<tag>-a<n>.json; via dispatcher transport]--> RUNNING
  RUNNING --[dispatch-<tag>-a<n>.json captured envelope; via envelope extraction]--> EVIDENCE_PENDING
  EVIDENCE_PENDING --[verify-<tag>-a<n>.json + canonical WORKER_COMPLETED event_id; via verifyResultEnvelope + recordVerifiedResult]--> VERIFIED
  VERIFIED --[99-close.json assessment; via assess + close]--> CLOSED
  Side exits: PLANNED|AUTHORIZED|QUEUED|RUNNING --> BLOCKED (policy JSON: REQUIRES_HUMAN_APPROVAL/PROHIBITED or precondition missing); RUNNING --> FAILED (worker-reported failed, attempts exhausted; via classifyRetry exhaustion); EVIDENCE_PENDING --> FAILED (valid envelope, status=failed; via verify + record + classifyRetry); EVIDENCE_PENDING --> VERIFICATION_FAILED (invalid envelope; non-retryable, terminal for the unit); RUNNING --> VERIFICATION_FAILED (protocol failure: no parseable envelope). BLOCKED --> PLANNED (re-plan from evidence) | CLOSED (human abandon). FAILED --> PLANNED (re-plan from recorded failure) | BLOCKED (human disposition). Terminal: FAILED, VERIFICATION_FAILED, CLOSED.
Attempt lifecycle (from objective-runtime.js + orca_control_loop.js): DISPATCHING --[transport settles; rendezvous collected]--> TRANSPORT_SETTLED --[envelope extracted | PROTOCOL_FAILURE]--> OUTCOME in {ACCEPTED, WORKER_FAILED, VERIFICATION_FAILED, TIMED_OUT}. Guard: attempt record precedes dispatch; dispatch_pid killed on coordinator timeout so a TIMED_OUT record is never mistaken for in-flight work.
ResultEnvelope lifecycle: ISSUED -> EXTRACTED (or PROTOCOL_FAILURE, terminal for attempt) -> VERIFIED {valid} -> RECORDED (WORKER_COMPLETED|WORKER_FAILED, logical_id=result_id) | INVALID (terminal for attempt, non-retryable).
Mission side (mission_runtime.js, for the MissionAuthority boundary): created -> assigned (claim, 60-second lease) -> running -> completed | failed; failWithRetry: running|assigned -> retry_pending (retry_at) -> running ... exhaustion -> failed. The ORCA loop deliberately does NOT mint MissionRuntime missions; its mission_id is an ORCA-scoped correlation label.

## PART 4: Executor-attribute rule
Language (JS/Python), provider (Hermes/Codex/Ollama/Copilot broker/cloud-subagent), transport (oneshot-subprocess, exec-subprocess, http, file-drop), host/runtime are ATTRIBUTES in the executor profile and the attempt record (invocation metadata, evidence.host, attempt metadata), never in the WorkOrder envelope and never inputs to identity derivation. Executor selection = authorization (profile key + capability allowlist + PENDING_AUTH/blockedExternal gates) + dispatch (transport). Classification: hermes_dispatch.py and JS/Python runtimes = EXECUTOR; codex = EXECUTOR-registered, transport pending; opencode legacy desktop profile = SUPERSEDED by the live OpenCode CLI row; Temporal = MECHANICS; ORCA loop = ORCHESTRATOR/consumer (plans/assesses/proposes, owns no business state); MissionRuntime lease = mission-level, not attempt-level.
