# PROBE-001 result: worker replacement from durable state alone — PASS (2026-09-23)

Question: does the autonomous-mission substrate support real work — specifically, can a replacement worker with zero conversational context reconstruct task state from durable records alone after the original worker is killed mid-attempt?

## Design
- Durable state: `probe-001/` — mission.json (goal, authority, budget, stop conditions), task-1/task.json (objective, claim, write scope, prohibitions), task-1/attempt-1.json (steps_completed, checkpoints), audit.jsonl (append-only event log).
- Worker A (attempt-1, IMPLEMENTER): 3-chunk analysis of the CRX mechanism library, atomic writes, per-chunk checkpoint + audit event. After chunk-2: create `awaiting-replacement.signal`, block on a sentinel that never arrives.
- Coordinator kills worker A mid-block via subagent.close, records `worker_killed_mid_attempt` in the audit log.
- Worker B (attempt-2): spawned fresh with ONLY the directory path `/home/hatch/workspace/autonomous-missions/probe-001/`. No transcript, no hints. Instructions: reconstruct from records, complete only what remains, no blind retry, stop and report ambiguity instead of guessing.

## Verdict (all independently verified from filesystem + audit log)

| Criterion | Result |
|---|---|
| Replacement completed the task from durable records alone | YES — chunk-3.md written 17:52:18, task.json → completed |
| No blind retry of completed work | YES — chunk-1.md mtime 17:51:44, chunk-2.md mtime 17:51:49, untouched |

| Audit trail continuous | YES — created → claimed → checkpoint ×2 → killed → attempt_started → task_completed |
| Ambiguity handling | Not triggered — state was unambiguous; the stop-on-ambiguity instruction was armed but unneeded |

## Honest scope limits
- Durable store was workspace-local JSON/JSONL, not the live PING event substrate or the event-to-mission bridge. Proven: the minimal identity/claim/checkpoint/audit convention suffices for cold reconstruction. Not proven: the same through ping_events at scale.
- Kill was a clean coordinator shutdown of a blocked worker, not a hard crash mid-write. Atomic (.tmp + rename) writes were used; torn-write recovery was not exercised.
- Single mission, single task, single replacement. Multi-attempt contention, lease expiry, and coordinator death are untested (Phase 5).

## Decision
Substrate assumption NOT falsified at this level. Proceed to parallel lanes (capability matrix, GitHub pipeline, Orca archaeology, observability) per the directive. Phase 5 adversarial recovery runs on synthetic missions first, per standing law.
