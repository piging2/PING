## Finding 1
Cohesity introduced Cohesity Agent Resilience on September 16, 2026, announced at Cohesity Catalyst in London. It is a new Cohesity Data Cloud capability that discovers, protects, and recovers the infrastructure behind enterprise AI agents. At launch it protects agent memory and configuration using the same snapshot architecture, immutable backups, and clean-room recovery that Cohesity uses for other workloads across on-premises, cloud, and SaaS environments. It has two core functions: protecting agent state, with point-in-time recovery to restore agents to a known-good state following memory corruption, misconfiguration, or malicious activity, and protecting what agents manage, meaning databases, file systems, and other services agents interact with, so affected resources can be precisely recovered. An agent topology view gives teams a unified view of each agent, including its memory stores, connected applications, databases, and supporting infrastructure. At launch it integrates with Amazon Bedrock, with support for additional agent platforms including offerings from Microsoft and Google on the roadmap. It is available now to select customers, with general availability targeted for the end of 2026. Cohesity's fifth annual Global Cyber Resilience Report found that 56 percent of organizations said they were not well prepared to detect or contain unintended actions by AI agents and automated workflows, and 58 percent were not very confident in their ability to verify the integrity of AI models and related data following a cyberattack. Chief Product Officer Vasu Murthy said, "Detection can tell you an AI agent went off course. It cannot undo the changes." Srikanth Kuntamukkala, CIS Global Lead for Partner Sales at Cognizant, said being able to restore an agent's state, and the data it may have changed, could give teams a more practical way to manage that risk as agentic applications move into production. Cohesity also outlined a vision called Autonomous Cyber Resilience, which uses agentic workflows to automate its five-step cyber resilience framework, and launched the Cohesity AI Resilience Academy, starting with a free 25-to-30-minute self-paced course on AI resilience concepts.

## Finding 2
The open-source project mcp-memory-service shipped version 11.12.0 on September 14, 2026, its first release since active development moved back to GitHub on September 5, 2026, with 73 merged pull requests, 43 of them from outside the maintainer. It is an Apache 2.0 licensed, self-hosted persistent memory backend for AI agent pipelines, working with LangGraph, CrewAI, AutoGen, Claude Desktop, Claude Code, and other MCP or HTTP clients. Its stated capabilities include a 76-endpoint REST API, a knowledge graph with typed edges such as causes, fixes, and contradicts, autonomous consolidation with decay and compression, embeddings that run locally via ONNX so memory never leaves the operator's infrastructure, hybrid BM25 plus vector search, MCP protocol support, real-time SSE events, and per-agent scoping via an X-Agent-ID header. The project's own published comparison table, which is self-reported by the maintainer and not an independent test, describes Mem0 as proprietary with per-call API pricing, cloud-hosted privacy, no knowledge graph, no automatic consolidation, no on-premise embeddings, and no MCP protocol support, and describes Zep as enterprise-licensed with enterprise pricing, cloud-hosted privacy, a limited knowledge graph, and no automatic consolidation. The project self-reports retrieval benchmarks of 80.4 percent recall at 5 on LongMemEval overall (90.4 percent at 10) and 91.1 percent recall at 5 on its DevBench set, measured with all-MiniLM-L6-v2 embeddings and zero LLM API calls. The GitHub page states no publication date; the release date of September 14, 2026 is stated on the page itself. The filed image is the project's own dashboard tour animation, captioned on the page as MCP Memory Dashboard Tour.
