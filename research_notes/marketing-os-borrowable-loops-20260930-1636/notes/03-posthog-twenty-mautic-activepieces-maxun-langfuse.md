## PostHog — events → funnels → cohorts → experiments → learnings
- posthog.com FAQ via GitHub (https://github.com/posthog/posthog.com/blob/HEAD/contents/faq.mdx): event capture (autocapture + custom, anonymous + identified); SDKs/APIs; product analytics (trends, funnels, retention, SQL); session replays; heatmaps; feature flags (multivariant, rollouts); experiments; surveys; error tracking; logs; Workflows (event-triggered messages); LLM analytics (traces, cost); data warehouse; CDP destinations/batch exports; events→actions→cohorts→groups. MIT open source, 30k+ stars, 400+ contributors.
- Brainboard case study (https://github.com/rohitpaulk/posthog.com/blob/HEAD/contents/customers/brainboard.mdx): MQL→PQL→SQL funnel + OKRs in PostHog; conversion tracking; desktop conversion 20%→70% via layout/CTA experiments; mobile 12%→17%; "+350% improvement" tracked in trends.
- posthog.com customers (https://posthog.com/product-analytics-explorer/customers): claims — 30% more data than GA (autocapture), 10-20% conversion improvement, +30% registrations (funnels→session replays).
- Activation methodology (https://newsletter.posthog.com/p/wtf-is-activation-and-why-should?aid=rec3jwfgEM8ai7aaP): group 3-5 candidate activation events, 5-10 groups; SQL test correlation with 3-month retention; 30-day activation window for analytics, 14 days for experiments.
- Independent runbook (https://github.com/alethialabs-io/alethialabs/blob/HEAD/deploy/analytics/posthog-runbook.md): anonymous pre-login events auto-alias on identify(); cohorts (Activated / Paying / Stuck = did connector_connected but not deploy_succeeded in 7d); session replays filtered to Stuck cohort = highest-ROI debugging; don't use PostHog as billing source of truth.
- tech-talks-in blog (https://github.com/tech-talks-in/tech-talks-in.github.io/blob/HEAD/blog/2026-02-22-posthog-product-analytics.md): multi-domain tracking stitched blog→pricing→trial into one journey; ~30% funnel drop-off reduction via replays; organic search drove highest-quality (lowest churn) signups → shifted content investment.

## Mautic — segmentation → campaigns → triggers → journeys
- mautic/user-documentation campaign builder (https://github.com/mautic/user-documentation/blob/HEAD/docs/campaigns/campaign_builder.rst): conditions (date/deadline, custom date fields), delays (relative dates on conditions and actions), positive/negative paths; pattern: dynamic segment (date field = TODAY) as campaign source so contacts flow in/out daily.
- hawkhost.com tips (https://www.hawkhost.com/blog/2026-08-17-mautic-tips-and-tricks/): three required crons — mautic:segments:update (dynamic membership), mautic:campaigns:update (add eligible contacts), mautic:campaigns:trigger (execute scheduled events); stagger every 15 min; without cron automations silently do nothing.
- brauliosilveira repo (https://github.com/brauliosilveira/email-automation-mautic-ses/blob/HEAD/README.md): engineering decisions — Mautic as lifecycle brain (forms, tracking, scoring, tags, campaigns, segments); preserve visitor history beyond conversion; dynamic tags/segments; UTM capture first-class; attribution built into contact lifecycle.
- Case studies (mautic.org): Addiko Bank (https://mautic.org/case-study/addiko-bank/) — Sales Snap/Mautic, quiz lead magnet, segmented drip emails, 2M+ individuals reached, above-industry read rates, more calls booked/branch visits. Haugan Cruises (https://mautic.org/case-study/haugan-cruises/) — 15 lists → 1 list, 12 personalized emails/newsletters, 22% avg read rate; content reused across segments; quote: previously content created ad-hoc and used once; "fragmented tool landscape, no clear statements about added value." Cash in Time (https://mautic.org/case-study/cash-in-time/) — 50% calls→survey, finer behavioral segmentation, up to 56% open rate, campaign = 30% of marketing automation revenue in Jul-Aug. Prospectiva (https://mautic.org/case-study/prospectiva/) — ROI +80%, lower opt-out, freed HR to strategy. Leuphana University (https://community.mautic.org/processes/mautic-awards-2025/f/109/proposals/190) — 75% manual workload reduction, GDPR-compliant self-hosting.

## Langfuse — trace → evaluate → dataset → improve
- Langfuse docs index (https://github.com/langfuse/langfuse-docs/blob/HEAD/md-override/index.md): "The AI engineering loop — tracing, monitoring, datasets, experiments, evaluation in one continuous loop"; vendor scale claims: 21 of Fortune 50, 100k+ engineers, 90B+ observations/month.
- Blog: evaluate AI agent skills (https://github.com/langfuse/langfuse-docs/blob/HEAD/content/blog/2026-02-26-evaluate-ai-agent-skills.mdx): store user prompts as Datasets → run Experiments → trace behavior → score → iterate skill → re-run; same loop as OpenAI's Codex skill evals (JSONL traces + deterministic graders).
- Blog: AI agent observability (https://github.com/langfuse/langfuse-docs/blob/HEAD/content/blog/2024-07-ai-agent-observability-with-langfuse.mdx): offline — build datasets from failing production traces + hand-written edge cases → experiments compare change vs baseline → gate releases in CI; online — reference-free evaluators + user feedback score live traffic; new production failure → new dataset item. Binary pass/fail scores preferred over 1-5 scales.
- awesome-agent-native-services (https://github.com/haoruilee/awesome-agent-native-services/blob/HEAD/services/observability-and-tracing/langfuse.md): protocol surface — Python/TS SDKs, OTEL-compatible, native integrations (LangChain, LangGraph, OpenAI Agents SDK, Claude SDK); evaluation workflow diagram; use cases: debugging failed runs, prompt optimization, cost optimization, CI regression detection.
- Elementor engineers independent article (https://medium.com/elementor-engineers/why-logging-isnt-enough-for-llm-systems-and-how-observability-fixes-it-018e528e9f89): traces of embeddings→RAG→LLM→tool calls→post-processing with inputs/outputs/latency/tokens; prompt versioning with diffs linked to traces; drift detection; CI/CD integration.
- GGX docs integration (https://github.com/corridor/ggx-docs/blob/HEAD/src/content/docs/integrations/observability/langfuse.md): trace-to-review workflow — send traces/scores/feedback to governance layer → route to judge/human review → promote to ground truth → failing traces become bugs → feed simulations and judge development.
