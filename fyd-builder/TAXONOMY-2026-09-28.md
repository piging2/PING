## Determination: YES — the existing `FactClass` vocabulary is authoritative

Source: `src/fyd/proceduralize/proceduralizer.ts` (extraction pipeline emission choke point,
Grill 7). Persisted per-field via `fieldClasses` (`Record<objectId, Record<field, FactClass>>`),
flows into the Ask bounded context (`ask-composer.ts`), into lineage/proof records
(`lineage/tracer.ts`, `acquisition/arrow2-proof.ts`), and into `AskClaimClassification`.

Existing semantics (verbatim from the type doc):

- `DIRECT_FACT`: read verbatim from an observed source (JSON-LD literal, meta tag, feed
  entry). Confidence 1.0.
- `DERIVED_FACT`: deterministic transform of direct facts (coarsened locality, assembled
  address string, platform label from a URL host).
- `INFERENCE`: heuristic or AI guess. The pipeline emits none by default; the slot exists
  so a future intelligence step is labeled.
- `GENERATED_COPY`: copy written by the generator lane, not the extractor.
- `USER_OVERRIDE`: owner-supplied edit applied via the patch lane.

## Mapping to Nolan's four terms (1:1, no semantic drift)

| Nolan term      | Existing term   | Semantic match |
|-----------------|-----------------|----------------|
| OBSERVED        | DIRECT_FACT     | exact: directly obtained from an identified source/observation |
| INFERRED        | INFERENCE       | exact: concluded by reasoning from observations, not directly stated |
| DERIVED         | DERIVED_FACT    | exact: mechanically/computationally produced by a known transformation |
| OWNER_ASSERTED  | USER_OVERRIDE   | exact: supplied/corrected by the authorized owner |

`GENERATED_COPY` is a legitimate FIFTH canonical state (generator-written presentation
copy). Nolan's own render-invariant rule requires it: factual render output must be bound
to evidence or explicitly classified DERIVED / INFERRED / GENERATED. Presentation may
collapse states; canonical provenance must not.

## Competing vocabularies to migrate (not invent around)

1. **Concierge grade fold** (`src/fyd/ask/concierge.ts`, `context-compiler.ts`, `visitor-answer.ts`):
   grades SUPPORTED / DERIVED / INFERRED / UNKNOWN. `visitor-answer.ts` documents
   "DERIVED" as folding DERIVED_FACT + INFERENCE + GENERATED_COPY into one class.
   This is the exact fold Nolan flagged. Migrate: split the grade axis so INFERRED
   stays distinct from DERIVED; map grades onto FactClass 1:1.
2. **`EPISTEMIC_RANK`** (`context-compiler.ts`): mixes `DEMO_SYNTHETIC`, `website_statement`,
   `owner_authorship`, `relationship_fact`, `provenance`, `unknown` with FactClass values.
   Migrate onto the canonical axis:
   - `DEMO_SYNTHETIC` → `GENERATED_COPY` (overlay/demo-authored copy is generator copy)
   - `owner_authorship` → `USER_OVERRIDE`
   - `relationship_fact` → `DIRECT_FACT` (a recorded relationship is directly observed)
   - `website_statement` → `DIRECT_FACT` (the site's own words are directly observed;
     the "never verified fact" nuance lives on the ClaimKind axis, not the epistemic axis)
   - `provenance` (bare) → `DIRECT_FACT` or remove; audit call sites first
   - `unknown` → explicit `UNKNOWN` (legitimate state, already rank 0)
3. **`classificationFromProvenance` fallbacks** (`src/lib/ping/ask-composer.ts`): same
   normalization as (2). The `ClaimKind` axis (`website_statement` | `feed_item`) stays as
   SOURCE GRADING — a different, orthogonal axis. Do not let source grading leak into the
   epistemic slot again.

## No-silent-promotion enforcement points (already exist — keep and extend)

- `provenance()` in `proceduralizer.ts`: the emission choke point; every `ExtractedField`
  carries factClass + visibility. INFERENCE is never emitted by default.
- `verifyAnswerClaims` epistemic-rank check (`context-compiler.ts`): a claim may not be
  presented at a higher epistemic rank than its best evidence (`epistemic_upgrade`
  violation). Keep the check; the rank ORDER is a separate design decision from the
  vocabulary normalization.
- Binding verifier (render invariant): extend to require every factual render output to
  carry one of the five FactClass values; unclassified factual claims fail.

## Recommendation

Keep `FactClass` as the canonical persisted vocabulary (storage-stable; Grill 7
guarantees; already flows through extraction → fieldClasses → Ask → lineage).
Document Nolan's four terms as the canonical HUMAN/API terms with exact 1:1 mapping at
the type definition. Migrate the three competing ask-layer vocabularies onto it.
Rename `USER_OVERRIDE` → `OWNER_ASSERTED` in a future storage migration only if the
persisted-value rename is worth the churn; "user" is ambiguous (visitor vs owner) but
the semantics are already owner-scoped via the patch lane.

Do NOT fold INFERRED into DERIVED anywhere. Do NOT let presentation collapse leak into
canonical records.
