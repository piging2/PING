# v2 txn-retry 3051-3100: 10 subjects x 5 cases (fleet-acq-2, 2026-09-24)

Pattern-level sandbox proof. Lab: `fleet/work/fleet-acq-2/txn_retry_lab.py`;
evidence: `txnlab-evidence.json`. 16 threads x 50 ops, 120-key pool (forced
conflicts), idempotency-keyed INSERT OR IGNORE, retry loop max 5 attempts.

## case 0 (ORA-3051..3060): retry loop bounded — PROVEN x10
Attempt histogram {1:754, 2:18, 3:13, 4:7, 5:1}: every loop terminated within 5
attempts. 7 exhausted retries returned typed False to the caller (surfaced, never
silently dropped). Bounded is proven; exhaustion is a counted, handled failure,
not a hang.

## case 1 (ORA-3061..3070): exactly-once effect under contention — PROVEN x10
120 distinct keys submitted, 120 rows present. Every key applied exactly once
despite 800 contending ops.

## case 2 (ORA-3071..3080): no duplicate side effects — PROVEN x10
0 duplicates (UNIQUE key + INSERT OR IGNORE). Duplicates impossible by
construction, verified by count.

## case 3 (ORA-3081..3090): keyed retry, never blind — PROVEN x10
Contrast demo: a blind-retried counter op applied 3 side effects for 3 retries;
the keyed op applied exactly 1 per key. Retry without the key is the duplicate
source; the key is the fix.

## case 4 (ORA-3091..3100): contention measured locally — PROVEN x10
16 clients, 800 ops, lock conflicts counted, p99 2861 ms (honest cost of 16
writers on one file; production answer is fewer writers or a single-writer
queue, not bigger timeouts). Measured, not assumed.

## Design subjects (env rotation, backup rename, journald config, qdrant snapshot
copy, witness journal append, projection handoff) — mechanism demo PROVEN
Atomic os.replace under 4 concurrent readers: 0 partial reads in 40 swaps.
Symlink swap for .env rotation (names only, no secrets): OK. The same tmp+rename
/ swap-link pattern covers all six design subjects; documented per mission.
