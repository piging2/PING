## wedged gateway with no healthcheck (container Up, event loop wedged)
1. Confirm wedge WITHOUT restarting: docker exec ping-gateway date + time a /health request;
   a healthy container that never answers while its event loop is wedged is the failure.
2. Preserve forensics first: docker logs --tail=all ping-gateway > forensics/gw-wedge.log;
   copy /opt/ping/config snapshot; node --report if reachable, else /proc/<pid> stack via gcore.
3. Restore forward: start replacement gateway container (candidate image) on scratch stores,
   shift traffic, THEN stop (do not rm) the wedged container so its dead state remains for analysis.
4. Add a real healthcheck to the run spec (HTTP /health, interval 15s, retries 3) so recurrence
   flips the container to unhealthy instead of lying Up.

## unattended-upgrades enabled with no operator coordination

2. Forward fix (no rollback of the agent): set Unattended-Upgrade::Automatic-Reboot "false",
   pin docker/containerd/kernel packages (apt-mark hold), schedule upgrades in a maintenance window.
